# 知乎草稿接入

## 能力边界

`ZhihuPublicationStrategy.prePublish` 使用 `ZhihuDraftBrowserClient` 创建知乎草稿，不再调用 Wechatsync。客户端从 `platform_browser_login` 读取已登录的知乎 Playwright `storageState`，在隔离浏览器中打开知乎编辑器、导入 Markdown、重新打开同一草稿核对标题、正文和图片，确认后返回 `DRAFT_CREATED`、`remoteContentId`、`draftUrl`。不会点击公开发布。

`ZhihuPublicationStrategy.publish` 保持原有 `ZhihuBrowserClient` 流程，使用独立 Chrome `profile-dir` 公开发布已有草稿。两个通道须登录同一个知乎账号；数据库登录态不会自动登录公开发布通道。

调用链：`ContentPublicationService.prePublishContent → PublicationPlatformStrategyRouter → ZhihuPublicationStrategy → ZhihuDraftBrowserClient → 知乎编辑器`。草稿创建和公开发布都不自动重试；如果浏览器操作后结果无法确认，应先人工核对知乎草稿箱。

## 准备与调用

1. 按 [浏览器登录配置](../src/main/resources/config/browser-login.md) 初始化登录表、安装 Playwright Chromium，并在浏览器登录管理中登录知乎。
2. 按现有内容优化和人工确认流程提交标题、Markdown 正文及 `ZHIHU` 平台，调用 `ContentPublicationService.prePublishContent`。
3. 收到 `DRAFT_CREATED` 后打开 `draftUrl` 核对草稿。审核通过、需要公开发布时，再按 [知乎公开发布配置](../src/main/resources/config/zhihu-publish.md) 调用 `publishDraft`。

Markdown 文件只在单次导入期间临时存在，结束后删除。远程 HTTP(S) 图片会随 Markdown 导入，并在回读时核对图片节点数量；本地路径与内嵌 `data:` 图片目前会明确拒绝，避免静默丢图。

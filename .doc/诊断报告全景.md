# 诊断报告全景

状态：2026-10-17 与用户确认的报告结构，尚未实现。指标计算、数据表及判定方式待详细设计。

## 分析口径

- 只分析成功的回答；调用失败、因输出上限截断（`finish_reason=length`）的结果不进入分析。
- 没有来源的回答不参与引用分析，但仍参与提及、推荐与态度分析。
- 各平台“引用”含义不同（豆包/OpenAI 为逐句引用，DeepSeek 为已打开网页，千问/智谱为搜索召回来源，文心为智能搜索网页），引用类指标只在同一口径的平台间比较。
- 以各模型的数据为主，跨模型汇总只作参考。

## 分析场景

同样是分析回答态度，问题类型和回答是否提到目标不同，分析对象与结论不同：

| 问题类型 | 回答提到目标 | 回答没提到目标 |
|---|---|---|
| 点名问题（直接问资产） | A 品牌口碑：模型怎么评价我们 | 几乎不会出现 |
| 非品牌问题（问品类、场景） | B 推荐态度：推荐我们时语气多强、带什么保留 | C 需求与期望：用户在意什么、对这类产品期待什么 |
| 对比问题（我们 vs 竞品） | D 相对评价：哪些方面赢、哪些方面输 | D' 竞品被评价的标准（未被列入对比本身就是问题） |

## 子 Tab 全景

| 子 Tab | 职责：回答什么问题 | 数据范围 | 分析维度 | 维度目的 |
|---|---|---|---|---|
| **① 诊断概览** | 这一轮整体表现怎么样、最该做什么 | 全部有效回答 | 样本说明 | 交代有效回答数、带来源的数量、模型数、题数和采样次数，让人知道结论有多少依据 |
| | | | 各模型核心指标 | 每个模型一行，列出提及率、推荐率、首推率、品牌正面率、推荐份额，看出我们在哪个平台弱 |
| | | | 主要发现 | 用 3–5 条结论概括问题，每条都能下钻看证据 |
| | | | 优先行动 | 列出最值得先做的 3 件事，链接到 ⑥ |
| **② 可见度与推荐** | 用户问到这类需求时，模型会不会主动想到我们、推荐得有多坚定 | **非品牌问题** | 提及率、推荐率、首推率、平均排名 | 衡量自然发现能力，也就是 GEO 的核心结果 |
| | | | 问题覆盖率 | 看我们在多少个场景里出现过，找出完全缺席的场景 |
| | | | 稳定性（重复采样） | 区分“偶尔被提到”和“稳定被推荐”，避免一次偶然就下结论 |
| | | | **推荐强度**（提到了目标时） | 首推、强推、并列、顺带一提、附带缺点、不推荐。提到不等于推荐得好 |
| | | | **保留意见**（提到了目标时） | 被推荐时附带的缺点，比如“价格偏高”，就是要补的短板 |
| | | | **用户需求与期望**（没提到目标时） | 回答强调的选择标准和用户顾虑排行，比如油品质量、杀熟。这些就是要补的内容方向 |
| | | | 按场景、意图拆分 | 找出我们在哪类场景强、哪类场景弱 |
| **③ 品牌认知** | 用户直接问到我们时，模型怎么评价、说得对不对 | **点名问题** | 情感倾向：正面、中性、负面 | 了解品牌在 AI 回答里的口碑 |
| | | | 正面点与负面点清单 | 正面点继续强化；负面点要回应或纠正 |
| | | | 负面来源 | 负面评价来自哪些网站，决定去哪里处理 |
| | | | 描述准确率与错误信息清单 | 找出价格、功能、归属上的错误或过时信息，附原文 |
| | | | 信息完整度 | 核心卖点、适用人群有没有被说到，判断模型对我们的了解够不够 |
| **④ 竞品对比** | 和竞品比，谁更容易被推荐、为什么 | 非品牌问题 + 对比问题 | 提及份额、推荐份额 | 我们在 AI 回答中的市场声量 |
| | | | 各竞品的提及率、推荐率、首推率 | 口径和目标相同，可以直接比较 |
| | | | 同题胜率 | 同一个回答里同时出现时，谁排在前面 |
| | | | **分维度胜负**（对比问题） | 每个比较维度上我们赢、输还是持平，找出劣势维度 |
| | | | 竞品被推荐的理由 | 只用回答里明确写出的理由，附原文 |
| | | | 竞品的优势场景 | 竞品在哪些场景里压过我们 |
| | | | 新发现的同类产品 | 列为待确认竞品，避免漏掉真正的对手 |
| **⑤ 引用与内容** | 模型的信息从哪来，我们的内容有没有被用上 | **带来源的回答**；同一引用口径的平台之间才比较 | 来源覆盖率与各平台引用口径 | 交代数据完整性，避免拿不同含义的“引用”直接比较 |
| | | | 自有来源引用率 | 官网、文档、官方账号有没有被引用 |
| | | | 第三方提及引用率 | 提到我们的第三方内容有没有被引用 |
| | | | 已发内容命中 | 和内容投放的发布记录比对，看我们发过的文章有没有被引用 |
| | | | 来源平台排行（按模型） | 各 AI 平台偏爱引用哪些网站和平台，决定内容往哪发 |
| | | | 竞品的来源 | 竞品被推荐，靠的是哪些内容支撑 |
| | | | 内容差距 | 用户关心的标准中，我们有没有对应内容、是否公开可访问 |
| **⑥ 优化建议** | 接下来具体改什么、怎么验证 | 汇总 ②–⑤ 的发现 | 排查原因的 6 个方向 | 场景匹配、选择依据、来源内容、内容覆盖、能否被找到和理解、认知准确性；允许得出“这道题不适合推荐目标” |
| | | | 建议的 6 个类别 | 补内容空缺、完善已有内容、增加可信证据、纠正和统一信息、改善公开访问与检索、补充第三方覆盖 |
| | | | 证据状态 | 标明是“回答明确表达”、“来源已核实”还是“待验证推测”，不把推测当结论 |
| | | | 优先级 | 每轮突出 3–5 条，写明依据：影响多少道题、在哪些模型上、差距有多大 |
| | | | 复测方式 | 用原问题、原渠道配置复测，口径一致时才和上一次对比 |

## 所有 Tab 共用

| 能力 | 目的 |
|---|---|
| 筛选：模型、问题组、场景和意图、语言 | 各 Tab 都按这些条件切换，不再为它们单独加 Tab |
| 下钻到回答原文 | 点任意数字都能看到对应的回答、判定依据和来源，结论可以追溯 |
| 口径说明 | 只分析成功的回答；没有来源的回答不参与引用分析；汇总数据只作参考，以各模型的数据为主 |

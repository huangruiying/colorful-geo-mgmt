# Workflow C —— 故障响应链（incident-response）

> 适用场景：告警 / 线上故障 / 报错 —— 从分诊到根因到收尾值班沉淀的完整响应链。
>
> 触发关键词："告警 / 报错 / 线上有问题 / 故障 / 排障 / RCA / 根因 / 慢 / 雪崩"
>
> 核心原则：**先分诊定位 → 再查根因 → 三类专项展开 → 值班沉淀闭环**，每跳带"现场快照"避免被新事件污染。

---

## 1. 串联顺序

```text
15 alert-triage                  告警分诊
    ↓
14 log-rca                       日志根因
    ├─→ 16 slow-sql              慢 SQL
    ├─→ 17 config-drift          配置漂移
    ├─→ 28 distributed-troubleshooting 分布式排障
    └─→ 09 code-review           代码评审（修复方案）
    ↓
23 oncall-knowledge              值班沉淀
```

---

## 2. 阶段定义

| 阶段 | Agent             | 目标                                | 验收                          |
|----|-------------------|-----------------------------------|-----------------------------|
| 15 | alert-triage              | 判断告警是否真故障 / 范围 / 优先级               | 出"故障等级 + 影响面 + 第一现场快照"        |
| 14 | log-rca                   | 用日志定位根因                            | 出"故障链路 + 触发条件 + 关键日志"          |
| 16 | slow-sql                  | 慢 SQL 专项分析（执行计划 / 索引 / 锁）            | 出"慢点 + 优化方案"                  |
| 17 | config-drift              | 环境差异 / 配置漂移检测                      | 出"漂移项 + 修复脚本"                |
| 28 | distributed-troubleshooting | 跨服务链路 / 雪崩 / 调用链异常                | 出"链路图 + 根因节点"                |
| 09 | code-review               | 修复方案评审（若需要改代码）                     | 修复 PR 含回归测试                 |
| 23 | oncall-knowledge          | 把本次故障写进 SOP / 故障手册                  | 沉淀成"下次怎么处理"的可复用文档           |

16 / 17 / 28 / 09 之间**可按需并发**，根据 14 的根因结论决定调用哪几条。

---

## 3. 输出契约

按 workflow.md 报告结果、证据和限制。**Findings 段必须含"现场快照时间戳 + 影响面"**。

---

## 4. 严守边界

- **不做新功能 / 重构**：故障期间最小修改原则，跨界路由 04 / 05
- **不省略 23**：每次故障必落档，否则故障会以同样方式重复发生
- **风险升级**：影响面跨多服务 → 必加 28；涉数据库 → 必加 16

---

## 5. 触发示例

```text
"线上出现 500，看下日志"           → C
"告警群里说 X 服务有问题"          → C
"接口慢了，查下原因"               → C
```

| 关系             | 说明                                            |
|----------------|-----------------------------------------------|
| 与 Workflow B 区别 | B 是预防性扫描；C 是事后响应                              |

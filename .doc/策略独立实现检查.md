# 大模型抽象策略复用检查

核对日期：2026-10-14。按用户确认，将两个协议客户端改为抽象策略，五个具体策略通过继承复用协议交互。

## 最终职责

- AbstractChatCompletionsApiStrategy、AbstractResponsesApiStrategy 位于 strategy 包，实现 LLMStrategy，声明协议并维护配置校验、query、基础请求、HTTP、正文/引用及元数据解析。
- 通用 Chat 和 Responses 策略直接继承父类默认行为；OpenAI Chat、OpenAI Responses、豆包 Responses 仅重写 protected buildRequestBody，在 super 基础请求上调整厂商参数。
- 两个抽象父类不注册独立 Bean，五个具体策略及 Mock 的六个 Bean 名和页面选项保持不变。
- 父类通过 @Resource 注入同一个 llmRestTemplateWithTimeout；Spring 管理连接资源，不新增客户端层或连接池。
- LlmCitationParser 继续共用引用字段解析；无新搜索流程、策略注册表或厂商占位。

## 保持的请求契约

| 策略 | 参数职责 |
|---|---|
| ChatCompletionsApiCommonStrategy | Chat 基础文本请求，不声明搜索 |
| ChatCompletionsApiOpenAiStrategy | 仅精确匹配 gpt-5-search-api 时增加搜索选项并移除 temperature、max_tokens |
| ResponsesApiCommonStrategy | Responses 基础文本请求，不声明工具 |
| ResponsesApiOpenAiStrategy | web_search 与 required |
| ResponsesApiDoubaoStrategy | web_search、sources=[doubao] 与 required |

每次创建独立请求 Map，不复用可变请求体。可选参数留空不传；保持非流式独立问答、结构化引用、URL 去重、豆包摘要、整数位置、显式 JSON 空值及失败/不完整响应拒绝规则。Mock 行为不变。

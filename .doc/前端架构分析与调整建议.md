# 前端架构分析与调整建议

日期：2026-10-17。范围：当前工作区的全部自有前端 HTML、JavaScript、CSS，以及测试与资源加载方式。本轮只分析，不实施重构，不调用创建任务、模型、登录或发布接口。

## 1. 判断

当前适合保留原生 JavaScript 多页面结构，先整理公共基础能力、模块边界和回归测试。没有必要仅因代码由不同模型生成，就整体换成 Vue/React 或重新建设一套前后端分离工程。

真正的维护负担是同一种能力存在多份实现，并且行为已出现差异：请求错误处理、分页、弹窗、异步响应、状态文字、导航及样式。换框架本身不会解决这些差异。

建议优先顺序：请求边界 → 请求与弹窗生命周期 → 分页及公共展示 → 导航与基础样式 → 按职责拆复杂页面。每批独立验收，保留页面 URL、后端接口和业务动作。

## 4. 可以抽哪些，抽到什么程度

### 4.1 HTTP 请求：一个传输入口，不建万能业务客户端

公共层处理 JSON 序列化/解析、错误原因、响应为空、请求头及 AbortSignal。可保留 HTTP 状态供页面判断，不把“请求完成但刷新失败”混成“业务保存失败”。

不自动重试 POST/PUT/DELETE，不自动切换模型，不替页面决定“成功后关闭哪个窗口”。尤其任务创建已有 requestId 规则，不能被一个通用 retry 包装绕过。前端 abort 只代表停止等待，不能当作服务器已经取消任务或模型调用。

API 路径先保留在业务模块。只有任务详情/结果等确实跨页面使用时，才抽对应 API 方法，不给每个 fetch 都增加只有一行转发的 api/service/repository 层。

### 4.2 弹窗、轮询与异步请求：统一机制，业务条件留在原处

公共弹窗能力负责打开、关闭、ESC、遮罩、背景滚动和清理回调；保存中禁止关闭、未保存提示、登录取消仍由业务模块控制。不能一律注册“点击遮罩即关闭”，否则会破坏方案未保存保护和登录取消会话。

公共异步机制负责标识当前请求、旧响应失效、可选取消。公共轮询负责等待前次结束、安排下一次、停止和错误通知；“哪些状态算终态”由各模块提供。登录的 setInterval + polling 和任务的递归 setTimeout 都已有防重叠思路，应整理现有行为，而不是机械替换定时器。

### 4.3 展示组件：先小后大

- 继续共用 MarkdownView，仍只转换视图，编辑框、错误、原始响应保持原文。
- 共用引用列表与安全链接创建；诊断报告和任务都展示回答，但任务有状态、引用、用量、原始响应等附加信息，适合共用“回答正文与引用”小视图，元数据和业务动作各自维护。
- 共用状态徽标的视觉结构；诊断任务、报告、发布、登录的状态语义不同，字典按业务域分别放，不做全站万能 Status 枚举。
- 共用分页、消息提示、操作按钮状态、日期格式。日期先明确显示服务端时间还是浏览器本地时间，避免格式统一后含义变化。
- 普通表格先统一样式和空状态。方案问题表有编辑/候选/分页，报告指标表有数值列，发布表有平台动作，暂不建设万能配置化表格或 CRUD 页面引擎。

### 4.4 页面外壳和 CSS

公共导航从单一定义产生，页面保留稳定 URL 和页面标识。按钮、表单、弹窗、提示、表格视觉放到公共组件 CSS。颜色、间距、圆角等反复出现的值再提成少量 CSS 变量；无需为每个数值建立设计系统。

目前 `.text-button` 在内容与诊断页面甚至是不同外观，`.notice` 也有两种修饰类写法。统一前需要确认哪些差异是业务用途、哪些是历史复制，不应简单删除重复选择器。`#answer-content.markdown-body > p:first-child` 为跨页样式补丁，也应随公共回答容器整理。models.css 通过 nth-child 覆盖 projects.css 的布局，调整时改为明确的表单字段类。

## 5. 建议的逐步组织方式

这是一份目标示意，不要求立即创建所有文件或搬动全部目录：

```text
admin/
  *.html                    保留现有页面 URL
  shared/
    http.js                 JSON 请求、响应与错误
    pagination.js           页码与全量选项读取
    dialog.js               弹窗通用行为
    polling.js              串行刷新与清理
    feedback.js             消息与按钮状态
    format.js               日期等纯展示函数
    navigation.js           菜单和页面信息
  components/
    markdown-view.js/css     现有公共正文组件
  diagnosis/
    labels.js               诊断域展示字典
    answer-view.js          实际跨页面复用的回答展示
  publishing/
    labels.js               发布域状态文字
    draft-entry.js          现有草稿入口逻辑
  styles/
    base.css                字体、变量与基础元素
    layout.css              外壳、导航、页面布局
    components.css          按钮、表单、弹窗等
  vendor/                   固定版本第三方库与许可
  原有页面脚本与样式           逐页缩减为业务编排和布局
```

先按实际复用创建文件；如果某文件只有一处使用且没有独立职责，保留在页面。顶层脚本可逐页转为 ES Modules，使依赖显式；Markdown 等传统第三方库需验证加载顺序，不通过批量修改 script 标签来一次性切换全站。不需要为了使用原生模块就新增 npm 安装或打包过程。

## 6. 分批落地与验收

| 批次 | 范围 | 验收重点 |
| --- | --- | --- |
| 第一批 | 公共 HTTP 封装，在项目与模型页试用；整理现有测试入口 | ProblemDetail、204、非 JSON、取消、headers；保存失败恢复按钮；密钥不输出；创建不重复提交 |
| 第二批 | 诊断任务/报告的弹窗与请求生命周期，补全报告候选分页 | 快速切换回答不串数据；关闭不回填；临时失败有提示；终态停止轮询；超过 100 条任务仍可选 |
| 第三批 | 向内容/发布/登录迁移共用请求及分页；统一字典、日期、引用 | 最终稿编辑与提交原文不变；未知提交结果不自动重试；扫码取消与切换仍正确 |
| 第四批 | 公共导航、按钮/表单/弹窗 CSS；移除页面间样式依赖 | 11 页链接/高亮、桌面/窄屏、长正文、长表格、嵌套弹窗和焦点检查 |
| 第五批 | 仍然复杂的任务、方案、登录页面按职责拆分；统一资源版本维护 | 业务行为回归，资源引用完整，入口文档清晰；避免纯搬文件制造大差异 |

前三批可以只修改前端源码及测试，不要求更改现有后端接口、数据库或策略。第四批涉及全站视觉，宜单独确认并回归。迁移 Vue/React、前后端独立部署、路由框架、全局状态库、万能表单/表格和完整设计系统均不列入本次建议首批范围。

# 04 代码实现

## 职责

根据已确认目标和接口边界实现最小可运行变更，复用项目已有能力。
不扩展产品流程，不新增无意义架构层；测试与复核由后续阶段负责。

## 执行

按 [代码变更流程](../../workflows/code-change-flow.md) 的接手、加载、实现和自检阶段执行。
架构以 [项目约定](../../rules/project-conventions.md) 和 [架构检查](../../rules/architecture.md) 为准。
Java 注释以 [comment-java.md](../../rules/comments/comment-java.md) 为准，通用原则见 [comment.md](../../rules/comment.md)。
必须真实读取适用规则；不假定其他工具自动注入，不在此重复维护硬规则。

## 交给测试与评审的证据

- 变更目标、文件和输入输出契约。
- 公共流程要求的逐方法注释审计与适用架构检查结果。
- 实际验证结果、阻断及未完成项。
- 正常、异常和边界行为，供 06 选择有意义的验证。

缺必要注释、规则加载或架构证据时先修正，不宣称完成。
后续顺序：06 验证 → 09 复核；用户要求真实/全量回归时再进入 F。

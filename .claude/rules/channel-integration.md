# 支付通道对接规范

> **最高优先级专题规则**：凡涉及支付通道状态映射，本文件优先于通用命名、重构和既有通道实现风格；不得以历史代码写法为由绕过本规范。外部接口契约和已经确认的业务语义仍必须保持不变。

## 1. 状态映射

所有新支付通道对接必须使用枚举集中声明通道状态与 pay-center 内部状态的映射关系。

每个状态枚举至少包含：

- 通道状态值
- 状态说明
- pay-center 内部状态
- 状态查找映射表
- 统一的 `getByStatus` 查询入口

支付状态与退款状态语义不同时，必须拆分为两个独立枚举，禁止通过可空字段混在同一个枚举中。

## 2. 未知状态

每个通道必须明确未知、空值和大小写处理策略，并通过单元测试固定行为。禁止依赖 `switch` 的隐式 `default` 表达业务策略。

## 3. 调用边界

- Handler 只消费枚举映射结果，禁止散落通道状态 `if/switch`。
- 响应字段解析与状态映射分离，枚举不负责解析 JSON 或执行外部调用。
- 支付、退款查询与回调必须复用同一套状态枚举。
- 禁止为单个状态映射引入无实际复用价值的接口或抽象类。

## 4. 测试要求

状态映射单元测试必须覆盖全部已知状态、未知状态、空值以及通道可能返回的大小写差异。

## 5. 交付检查

- 查询与回调是否复用同一状态枚举。
- Handler 中是否仍散落通道状态字符串或状态 `if/switch`。
- 枚举是否只负责状态映射，不解析 JSON、不执行外部调用。
- 支付状态与退款状态是否按业务语义拆分。
- 未知状态策略是否有对应单元测试。

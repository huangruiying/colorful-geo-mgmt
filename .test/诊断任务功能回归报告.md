## 真实 API 与 MySQL

可重复脚本：`diagnosis-task-api-test.py`。仅使用本轮随机标识创建临时资料，正常结束自动清理；`--keep-fixtures` 用于浏览器验收，之后使用 `--cleanup-prefix` 精确清理。

```bash
python3 .test/diagnosis-task-api-test.py --base-url http://127.0.0.1:8016 --database colorful_geo_diagnosis_qa_2f6426ff6ed3
```

该命令要求测试库与对应服务已准备好，不自动修改服务连接或创建数据库。默认参数针对本地业务库；共享库必须先统一运行版本。脚本连接凭据从容器环境读取，不在参数或报告中写入。

| 场景 | 验证结果 |
|---|---|
| 并发创建和重复提交 | 两个并发请求及后续相同提交返回同一任务 ID，未重复初始化采样 |
| 方案编辑后的快照 | 编辑来源方案的问题和名称后，历史任务仍保留原内容 |
| 双协议成功 | 2 问题 × 2 渠道 × 2 次得到 8 条独立成功采样 |
| 结果元数据 | 正文、结构化引用、实际模型、用量、耗时、结束原因和脱敏响应体均落库回读 |
| 分页与接口错误 | 摘要不携带大段正文/原始响应；分页、404、非法筛选、跨任务读取拒绝正确 |
| 部分与全部失败 | 限流失败继续其他采样；计数与终态正确，没有自动重试 |
| 空回答 | HTTP 200 但空白正文标记失败，不计成功、不重试 |
| 渠道配置变化 | 修改生成参数后，未开始的对应渠道采样失败，没有使用新参数继续调用 |
| 创建事务回滚 | 限定测试问题 ID 的临时插入触发器使创建失败，任务及采样全部回滚 |
| 结果保存失败 | 限定测试问题 ID 的更新触发器使回答保存失败，只调用模型一次，停止后续采样并终止任务 |
| 实际 HTTP 请求 | 单条 user 问题，无项目背景、无历史回答；留空随机性不发送；两协议生成参数字段正确 |
| 服务重启恢复 | 保存 1 成功、1 执行中、1 待执行的临时任务；重启后保留原回答，剩余 2 条失败，终态 PARTIAL_FAILED，无新增采样 |

触发器只用于故障注入，创建/删除通过容器已有管理员环境，测试结束全部移除；未关闭任何数据库校验或证书验证。

# 09 代码复核

## 职责

复核变更的职责、可读性、注释、异常、上下游契约及验证证据。
不代替真实平台联调，也不为遵守形式强制增加架构层。

## 加载与检查

按 [代码变更流程](../../workflows/code-change-flow.md) 的注释、架构、验证与交付阶段复核。
实际工程边界以 [项目约定](../../rules/project-conventions.md) 为准。
Java 变更必须读取 [Java 注释规则](../../rules/comments/comment-java.md)，按完整变更方法检查，不能只按行数或分支数量判断。
设计变更读取 [架构检查](../../rules/architecture.md)；其余规则按公共流程触发条件加载。

## 必需证据

- 逐方法审计是否列出了真实业务阶段，是否有对应的职责、分段/编号及决策注释。
- 类的职责/入口/边界是否准确，修改后有无过时说明。
- 实际层次、抽象必要性、数据模型职责、资源所有者和兼容契约是否符合项目约定。
- 测试是否验证实际行为，已完成与无法运行的检查是否分别记录。

沿用同一张审计表逐项复核，不只接受“已按规范检查”的声明。
缺 Java 必需注释或验收证据属于阻塞项，回到实现阶段修正；不能因为编译通过放行。

## 输出

有问题给出文件/方法、原因、影响和可执行修正；阻塞与非阻塞分开。
无问题报告已核对范围和验证限制，不重复完整规范。

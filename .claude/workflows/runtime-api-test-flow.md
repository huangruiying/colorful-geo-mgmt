# Workflow F —— 运行时接口回归链（runtime-api-test）

> 适用场景：开发完成后、用户指定接口 / curl / `.test` 文档 / 当前分支 diff，需要真实请求服务并形成测试报告。
>
> 核心原则：**真实请求 → 日志归因 → 只修代码问题 → 重启回归 → 报告落地**。

## 0. 强制引用

- 执行前必须加载 `agents/builders/31-runtime-api-test.md`、`rules/runtime-api-test.md`、`rules/testing.md`。
- 启动 / 重启 / 编译 / 脚本执行必须按 `rules/runtime-api-test.md` 读取 IDE 真实配置；IDE 只作为 JDK / Maven / Python / 工作目录 / 参数 / 环境变量来源，服务由自动化命令等价启动，不操作 IDE GUI。
- 单次自愈、外部依赖临时 mock、临时代码、测试数据、日志归因、报告字段、非常规处理、已知陷阱均以 `rules/runtime-api-test.md` 为唯一细则来源，本 Workflow 不重复维护。

---

## 1. 接口契约确认

测试前先确认接口契约，尤其是“下拉、候选集、支持项、名称列表、support”类接口。不得仅因请求体包含某字段，就默认该字段是强过滤条件。

字段语义必须先归类：

- 强查询条件：传错值应返回空
- 辅助选路条件：只参与部分候选计算
- 前端上下文参数：可能不参与过滤
- 兼容字段：暂时保留但不生效

接口返回“看起来不符合预期”时，失败归因前先核对：该字段是否在当前接口契约中承诺参与过滤？只有答案明确为“是”，才能把“传入不存在值仍返回数据”归因为代码问题。

字段过滤语义不明确时，先查 Controller、Service、Mapper 调用链和历史接口文档；仍不明确时向用户确认。负向断言和代码修复必须排在契约确认之后。

已知教训：`support/routeNames` 的 `toCInvoiceBody` / `companyInvoiceType` 不是强查询条件；错误值仍返回路由不一定是 bug，可能符合候选集接口语义。

---

## 2. 闭环路径

```text
首轮测试
→ 读报告 / 日志归因
→ 明确代码问题
→ 自动最小修复一次
→ 读取 IDE 配置后命令行重启
→ 复测一次
→ 成功则报告通过；失败则停止并输出下一步建议
```

硬限制：自动修复最多 1 次，修复后重启最多 1 次，重启后复测最多 1 轮；复测失败不得再次进入 04 / 05。

---

## 3. 串联顺序

```text
31 runtime-api-test          真实接口回归
    ├─→ 14 log-rca           接口失败 / 日志异常时
    ├─→ 04 code-generation   确认代码缺陷且需小范围修复时
    ├─→ 05 refactor          确认结构性代码问题时
    ↓
31 runtime-api-test          修复 / 重启后单次复测
    ↓
21 pr-summary                需要 PR 摘要时
```

---

## 4. 阶段定义

| 阶段 | Agent | 目标 | 验收 |
|---|---|---|---|
| 31 | runtime-api-test | 识别接口、准备数据、真实请求、脚本和报告落地 | `.test/*_测试报告.md` 包含请求结果、日志证据、归因、回归 |
| 14 | log-rca | 接口异常时定位日志证据和异常链 | 结论能对应 trace / 栈 / 源码行 |
| 04 / 05 | code-generation / refactor | 只修复确认为代码问题的缺陷，自动修复最多一次 | 范围最小，符合注释 / 重构规则 |
| 31 | runtime-api-test | 服务重启后重新请求失败接口，复测最多一轮 | 回归结果写入报告，失败即停止 |
| 21 | pr-summary | 汇总修复和测试结果 | 可直接进入 PR 描述 |

---

## 5. 严守边界

- master 落后检查、两轮前置依赖检查、IDE 真实配置读取、数据增删限制、临时兼容清理均按 `rules/runtime-api-test.md` 执行。
- 环境问题、外部依赖问题、数据问题不长期改业务代码；写接口依赖 `ContextUser` / 登录态 / 权限时，无鉴权只记录限制，不做匿名兼容。
- 需要改代码时必须回到 04 / 05，不在 31 内越权大改；测试脚本和测试报告可以保留在 `.test/`。

---

## 6. 输出契约

按 `workflow.md` 五段输出。最终必须给出：

- 测试报告路径
- 通过 / 失败 / 未测接口清单
- 失败归因类型
- 保留测试数据
- 非常规处理清单和清理状态
- 如触发单次自愈：首轮失败原因、自动修复内容、重启方式、复测结论；复测仍失败时输出停止原因和下一步建议

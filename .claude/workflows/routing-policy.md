# 路由策略细则

本文件只在入口路由出现多候选、交互式选择或自定义编排时加载。普通单 Agent / 单 Workflow 任务不必加载。

## 自动模式

- 默认走自动模式：按 `CLAUDE.md §3` 场景表识别入口，再按 `§4` 加载对应 Agent / Workflow / rules。
- 用户显式指定 workflow 短代号或 agent 编号时，直接执行对应链路，不再询问。
- 用户上一轮已确认 workflow 且本轮明显延续时，复用上一轮选择。

## 交互模式触发

满足任一条件时，先让用户选择路由方式：

- 命中 ≥ 2 个 workflow / agent 候选
- 跨 ≥ 2 个 agent 组
- 关键词模糊但范围明显较大
- 风险升级追加 ≥ 2 个 agent
- 用户说"都执行了 / 一起跑 / 全做了"且前文存在多个候选

## 交互选项

用 1 道单选题让用户选：

- 命中度最高的预制 workflow（推荐）
- 命中度第 2 / 第 3 的预制 workflow（如有）
- 自定义编排

每个选项描述必须包含"链路 + 一句话适用场景"。

## 自定义编排

用户选择自定义编排时：

1. 只列出与本任务相关的 8-12 个候选 agent。
2. 按 `planners → builders → guardians → responders → stewards` 排序。
3. 输出执行计划，让用户显式确认。
4. 确认后逐跳加载，每次只加载当前 Agent。

## 与 30-agent-router 的边界

- 本文件负责入口层面的"选哪条路"。
- `30-agent-router` 负责已进入某条路后，多个 Agent 候选之间的仲裁。

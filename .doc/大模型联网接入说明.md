依据：[OpenAI 输出 token 与推理 token 说明](https://developers.openai.com/api/docs/guides/reasoning)、[OpenAI GPT-5.2 参数限制](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.2)、[方舟 Responses 创建请求参数](https://docs.volcengine.com/docs/ark/create-model-responses-api?lang=zh)。方舟页面正文需要 JS，本轮参数依据其官方检索索引；具体模型接受情况仍待真实联调。

HTTP 交互已收敛到 [具名 RestTemplate 连接池](共用HTTP连接池.md)：两种协议模板按名称注入预注册的 llmRestTemplateWithTimeout，超时和证书配置统一取 application.yml 的 http.llm；渠道中的对应字段不再影响调用，不再使用动态工厂或每次创建 RestClient。

数据库 `geo_llm_channel.strategy_bean_name` 直接保存 Spring Bean 名。路由通过 Spring 注入的 `Map<String, LLMStrategy>` 获取实例，不反射，不手工注册编码，不自动切换策略。

`LLMStrategy` 只保留 `query` 和 `protocolType`。两个抽象父类复用协议调用和引用解析，子策略处理厂商请求差异。自建 LLMStrategyRegistry 及 strategyType/strategyCode/strategyName 方法已删除。

路由使用单次 selectOne（固定 LIMIT 1）定位渠道，直接将数据库实体交给策略，不再复制为 LLMConnectionConfig，也不另行传递密钥。远程空密钥在调用前拒绝，HTTP 请求头读取当前渠道密钥；实体的密钥不参与 toString 或接口响应。已删除无调用的 LangChain4j 方法和三个依赖，测试入口移除两层纯转发，原 HTTP 接口保持不变。

不再维护策略中文名称枚举或 strategyName 响应字段。页面使用数据库渠道名称、模型名称，策略选项直接展示实际 Bean 名和协议，来源为 Spring 注入的策略 Map。

## 当前 Bean

| 数据库保存的 Bean 名 | 实际调用 |
|---|---|
| compatibleChatCompletionsApiStrategy | 兼容 Chat 普通问答，不注入搜索参数 |
| compatibleResponsesApiStrategy | 兼容 Responses 普通问答，不注入搜索工具 |
| openAiChatCompletionsApiStrategy | OpenAI Chat；gpt-5-search-api 添加搜索选项 |
| openAiResponsesApiStrategy | OpenAI Responses，要求 web_search |
| doubaoResponsesApiStrategy | 豆包 Responses，要求基础联网插件 |
| mockLlmStrategy | 本地模拟，无远程调用 |

供应商标识只作资料，实际行为由选择的 Bean 决定。协议从 Bean 推导并只读展示。Bean 重命名时需同步迁移数据库。

OpenAI/豆包仍需正确的地址、模型、Key 和工具权限。普通兼容渠道不假装联网；Kimi 的独立检索和 DeepSeek 的外部检索尚未实现，没有空厂商策略。

引用只来自明确的 url_citation，支持扁平和嵌套结构。不把正文 URL 或检索召回来源当成模型引用，没有引用不等于没有联网。

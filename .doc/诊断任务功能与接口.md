# 诊断任务功能与接口

## 已实现的使用流程

入口为「资产诊断 → 诊断任务」。点击「发起诊断」，选择已保存方案，核对项目、问题数、渠道、重复次数和预计调用次数，然后确认创建。

任务创建后在后台排队执行，关闭页面不影响采样。详情显示整轮与各渠道进度，回答按问题、渠道和重复序号分页；可进一步查看正文、引用、实际模型、Token 用量、耗时、结束原因和原始响应。执行中的详情每 3 秒刷新，结束或关闭详情后停止刷新。

任务详情与回答详情使用独立弹窗；冻结配置以只读分组表格展示本轮概览、项目资料、问题与模型配置。Token 用量和原始响应通过回答弹窗中的按钮打开只读子弹窗，分别展示中文指标表与格式化 JSON。用量保留厂商字段路径，零值显示 0、缺值显示未提供，不把缓存或推理子项重复计入总量。关闭子弹窗返回原入口；阅读期间保留父列表位置，已结束的回答不重复刷新。

当前不提供定时发起、取消或诊断报告。「发起诊断」按方案当前配置创建新任务；已有失败或部分失败任务可在详情中「重新发起」，只将本任务非成功结果恢复待执行，保留成功回答及原冻结配置。

## 执行与保存规则

- 创建事务锁定来源方案，冻结项目、方案、问题和渠道非敏感配置，分批创建全部采样。方案后续编辑不改变历史记录。
- 每次采样只向被测模型发送独立问题，不携带项目资料或前次回答。项目背景仅供历史展示与后续分析。
- 精确使用方案选定的渠道 ID，不按优先级换渠道，不用 Mock 自动降级。
- 渠道被删除、停用、策略失效或配置变化时，未开始的对应采样失败。密钥不进入快照，轮换密钥可以继续执行。
- 同一次创建提交复用 `requestId`。重复提交返回同一个任务；不同方案不能使用同一个提交标识。
- 模型失败继续其他采样，不自动重发。HTTP 200 但回答为空白同样失败。
- 模型已返回但保存失败时，停止该任务后续采样。数据库恢复后终止其未完成结果，已保存回答保留，不重发已发送请求。
- 整轮与渠道数量从采样结果实时聚合，不额外维护计数字段。

任务状态：`PENDING`、`RUNNING`、`SUCCEEDED`、`PARTIAL_FAILED`、`FAILED`。采样状态不含 `PARTIAL_FAILED`。全部结束后，至少一条成功且有失败则为部分失败；全成功为成功；没有成功则为失败。

完整快照在 `geo_diagnosis_task.plan_snapshot`；单题、单渠道快照在结果表的 `question_snapshot`、`channel_snapshot`。响应元数据未提供时为空，不根据请求配置伪造实际模型或用量；成功无引用保存空数组，不从正文猜测引用。普通大模型查询仍只输出 `content` 和 `citations`，新增元数据只供任务持久化。

## 运行与部署

后台默认启用，`diagnosis.tasks.enabled=false` 可以关闭该实例的执行组件，保留创建与查询接口。一个数据库只有一个实例持有会话执行锁；其余实例可以提供接口但不执行采样。默认一个任务运行、任务内串行采样，其余排队，不引入消息队列。

取得执行锁后处理上次中断的 `RUNNING` 任务：已保存成功结果保留，未完成采样标记失败，不自动重新发送不确定的调用。原 `PENDING` 任务继续排队。后台数据库错误会短暂退避，避免持续高频查询和日志刷屏。

已有旧执行表的库先执行 `018_diagnosis_exec_request_id.sql` 一次；本地业务库已执行。新库使用最新版 `001_init.sql` 或 `011_geo_diagnosis_task.sql`，不重复执行 018。001 中有固定的 `CREATE DATABASE / USE colorful_geo`，测试其他库时必须移除这两条输入语句，不能仅通过 mysql 的 `-D` 参数切换。

**共享业务数据库的所有实例应统一加载同一版执行代码。** 新接口与旧执行器混用会导致快照比较失败；只重启一个预览实例不能保证队列由该实例处理。本轮未替换原 IDE 和旧 jar 实例；独立验收使用临时库，结束后清理。真实厂商调用与回答质量仍待验证。

## 共同接口约定

提供服务：`colorful-geo-mgmt`。调用方：管理后台。沿用现有后台访问方式，本 Controller 未新增鉴权机制。所有接口均为新增，不改变诊断方案和普通模型查询契约。

响应直接返回 JSON，不额外包装 `code/data`。错误使用 Spring `ProblemDetail`，包含 `status` 和 `detail`。无效输入/配置为 400，缺失任务或回答为 404，数据库或内部快照处理失败为 500；SQL、认证信息与远程异常原文不返回页面。

### 任务响应字段

| 字段 | 类型 | 含义 |
|---|---|---|
| id / planId / projectId | integer | 任务及来源关联 ID |
| planName / projectName | string | 创建时冻结的名称 |
| status | string | 整轮任务状态 |
| progress | object | `total/pending/running/succeeded/failed`，均为整数数量 |
| channels | array | 各渠道 `channelId/channelName/progress`，名称取冻结配置 |
| snapshot | object | 详情才提供的完整非敏感快照，列表省略 |
| createdAt | string | 创建时间，ISO 本地日期时间 |
| startedAt / finishedAt | string | 实际开始/结束时间，尚无值时省略 |

快照包含 `version/planId/planName/repeatCount/project/questions/channels`。项目仅序列化已确认的资料字段；单题保留 `id/sortOrder/text/source/intent/brandScope/language`；渠道保留 `id/channelCode/channelName/providerCode/strategyBeanName/protocolType/baseUrl/baseUrlDigest/modelName/temperature/maxTokens`。地址展示移除认证、查询串与片段，地址摘要用于变化检查，独立 API Key 不参与快照或摘要。

### 回答响应字段

| 字段 | 类型 | 含义 |
|---|---|---|
| id / taskId | integer | 采样及所属任务 ID |
| questionSortOrder | integer | 创建时问题序号，从 0 开始，页面显示加 1 |
| questionText / questionSnapshot | string / object | 冻结的问题及分类信息 |
| channelId / channelName / channelSnapshot | integer / string / object | 冻结渠道及非敏感配置 |
| repeatIndex | integer | 本题本渠道第几次采样，从 1 开始 |
| status | string | 单次采样状态 |
| answerText | string | 回答正文，详情且已返回时提供 |
| citations | array | 接口提供的结构化引用，每项 `url/title/startIndex/endIndex/snippet`；位置可为空，成功无引用为空数组 |
| modelName | string | 接口返回的实际模型，未提供时省略 |
| usageInfo | object | 接口返回的原始用量字段，未提供时省略 |
| durationMs | integer | 耗时毫秒，尚未调用时省略 |
| finishReason | string | Chat 结束原因或 Responses 状态，未提供时省略 |
| rawResponse | string | 已移除认证信息的响应体，仅详情返回 |
| errorMessage | string | 安全失败原因，未失败时省略 |
| startedAt / finishedAt | string | 本次采样的开始/结束时间，未提供时省略 |

以下示例展示关键字段；完整定义以上表为准，未赋值字段省略。

## 接口一：创建诊断任务

### 重新发起已有任务

`POST /diagnosis-tasks/{id}/restart`，无请求体，成功返回 200 和当前任务详情（与详情接口同结构）。后台可能在回读前已领取，返回状态可能为 PENDING 或 RUNNING。

仅 FAILED、PARTIAL_FAILED 任务允许操作。事务内锁定主任务，将非 SUCCEEDED 明细恢复 PENDING，清空旧响应、失败原因、耗时及开始/结束时间；主任务也恢复 PENDING，清空开始/结束时间。成功回答、任务 ID、创建时间、提交标识和冻结配置均保留，不生成新任务，不直接调用模型。

待执行、执行中或全部成功的任务，以及没有非成功明细的任务返回 400；任务不存在返回 404；存储失败返回安全的 500。主记录行锁让并发重发与后台领取串行，重复提交到已排队的任务会被拒绝。渠道配置如果与原快照不同，后台仍会拒绝执行，需另建任务。

### 创建新任务

`POST /diagnosis-tasks`，成功返回 201。相同提交回读原任务也返回 201。

```json
{"planId":1,"requestId":"2a60ccb6-567f-4565-a6da-cc4a45ea1d26"}
```

| Request 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| planId | integer | 是 | 无 | 已保存且有效的方案 ID，必须大于 0 |
| requestId | string | 是 | 无 | 1–64 位 ASCII 字母、数字、短横线或下划线；同次提交重用，重新执行使用新值 |

```json
{"id":42,"planId":1,"planName":"示例方案","projectId":2,"projectName":"示例项目","status":"PENDING","progress":{"total":4,"pending":4,"running":0,"succeeded":0,"failed":0},"channels":[{"channelId":7,"channelName":"示例渠道","progress":{"total":4,"pending":4,"running":0,"succeeded":0,"failed":0}}],"createdAt":"2026-10-13T12:00:00"}
```

Response 为任务响应，包含完整快照。参数、失效配置或标识跨方案复用返回 400；来源方案缺失返回 404；初始化失败返回 500，事务完整回滚。网络结果不确定时，保留原 `requestId` 再提交，不生成新值。

## 接口二：任务列表

`GET /diagnosis-tasks`，成功返回 200。

```json
{"planId":1,"status":"RUNNING","page":0,"size":20}
```

上例为查询参数说明，实际使用 URL 查询串，无请求体。`planId/status` 可选且默认不筛选；`page` 默认 0、不能为负；`size` 默认 20，允许 1–100。任务状态见共同定义，未知状态或分页非法返回 400。

```json
{"items":[{"id":42,"planId":1,"planName":"示例方案","projectId":2,"projectName":"示例项目","status":"RUNNING","progress":{"total":4,"pending":2,"running":1,"succeeded":1,"failed":0},"channels":[],"createdAt":"2026-10-13T12:00:00"}],"total":1,"page":0,"size":20}
```

Response 的 `items` 是任务摘要，不含 `snapshot`；`total` 为筛选后任务数，`page/size` 为当前分页。按任务 ID 降序展示，配置读取失败返回 500。

## 接口三：任务详情

`GET /diagnosis-tasks/{id}`，成功返回 200。无请求体。

```json
{"id":42}
```

上例说明路径参数；`id` 必填，为任务 ID。

```json
{"id":42,"planId":1,"planName":"示例方案","projectId":2,"projectName":"示例项目","status":"SUCCEEDED","progress":{"total":4,"pending":0,"running":0,"succeeded":4,"failed":0},"channels":[],"snapshot":{"version":1,"planId":1,"planName":"示例方案","repeatCount":2,"project":{"id":2,"name":"示例项目"},"questions":[],"channels":[]},"createdAt":"2026-10-13T12:00:00","startedAt":"2026-10-13T12:00:01","finishedAt":"2026-10-13T12:00:03"}
```

Response 是含完整快照的任务响应。示例省略集合内部内容；实际返回冻结的问题、渠道和项目资料。缺失任务返回 404，快照损坏或查询失败返回 500。

## 接口四：采样结果列表

`GET /diagnosis-tasks/{id}/results`，成功返回 200。

```json
{"id":42,"channelId":7,"status":"FAILED","page":0,"size":20}
```

`id` 是必填路径参数；其他字段为查询参数，无请求体。`channelId/status` 默认不筛选；`page/size` 与任务列表相同。`status` 只接受四种采样状态。

```json
{"items":[{"id":100,"diagnosisTaskId":42,"questionSortOrder":0,"questionText":"如何选择企业知识库？","questionSnapshot":{"text":"如何选择企业知识库？"},"channelId":7,"channelName":"示例渠道","channelSnapshot":{"id":7,"modelName":"示例模型"},"repeatIndex":1,"status":"FAILED","durationMs":1000,"errorMessage":"模型调用超时，请检查统一 HTTP 超时配置"}],"total":1,"page":0,"size":20}
```

Response 的 `items` 是回答摘要，不查询大段正文、引用、用量或原始响应。按问题序号、渠道 ID、重复序号排序；缺失任务返回 404，筛选非法返回 400，存储读取失败返回 500。

## 接口五：单次回答详情

`GET /diagnosis-tasks/{id}/results/{resultId}`，成功返回 200。无请求体。

```json
{"id":42,"resultId":100}
```

两个路径参数均必填，回答必须属于指定任务。

```json
{"id":100,"diagnosisTaskId":42,"questionSortOrder":0,"questionText":"如何选择企业知识库？","questionSnapshot":{"text":"如何选择企业知识库？"},"channelId":7,"channelName":"示例渠道","channelSnapshot":{"id":7,"modelName":"示例模型"},"repeatIndex":1,"status":"SUCCEEDED","answerText":"回答正文","citations":[],"modelName":"接口返回的实际模型","usageInfo":{"total_tokens":100},"durationMs":1000,"finishReason":"stop","rawResponse":"{\"model\":\"接口返回的实际模型\"}"}
```

Response 为完整回答定义，未提供值的字段省略。任务/回答不存在或回答属于其他任务返回 404；存储查询失败返回 500。普通模型问答接口不因此增加元数据字段。

# 独立 Playwright 浏览器登录（试验版）

这套登录流程保存的知乎浏览器会话已用于知乎草稿预发布。其他平台的独立浏览器登录仍待真实账号联调，预发布继续走 Wechatsync。浏览器登录态**不会**使旧“平台登录状态”页面或知乎公开发布浏览器自动登录。

## 首次启用

1. 全新数据库执行 `db/mysql/004_platform_browser_login.sql`；如果已执行旧版 004，则备份该表后执行 `db/mysql/005_simplify_platform_browser_login.sql`。旧版密文记录保留，但需要重新扫码才能写入可用会话。
2. 安装与项目 Playwright Java 版本一致的 Chromium 及运行依赖。当前父 POM 固定 Playwright `1.58.0`；Linux 部署需要对应系统依赖，不要只复制本机浏览器目录。
3. 启动 Java 服务并打开 `/admin/browser-login.html`。页面按平台展示已经核对过的入口：知乎支持扫码、短信和密码；微信公众号、掘金、微博、哔哩哔哩、今日头条、小红书、抖音、大鱼号支持扫码；简书、博客园、百度百家号、开源中国、思否、慕课网、网易号、人人都是产品经理、搜狐号支持部分或全部表单方式。其余枚举平台暂显示“待接入”，不因为能打开网站就开放按钮。

列表中的“接入状态”和“登录状态”分别表示是否曾保存经账号接口确认的会话、当前会话是否仍有效。“待验证”在页面的“接入状态”列自动展示，不需要人工标记：入口开放但尚未完成真实账号联调时显示“待验证”；不能因为登录页或二维码可见就显示“已验证”。用户完成登录后，服务端取得对应平台账号信息才会把 Playwright `storageState` 写入 `platform_browser_login`。手机号、密码与短信验证码仅用于当前登录页操作，不写入数据库。点击“检测”会从数据库恢复新的隔离浏览器上下文，再访问对应平台账号接口。网络故障或平台风控返回“无法确认”，不会直接标为失效。

暂未开放的枚举平台仍保留在列表中，显示灰色“待接入”。语雀、一点资讯等页面要求滑块或图形验证码，当前模态窗口尚不能完成这类交互。CSDN、东方财富等还缺可重复核验的账号闭环。这里的“待接入”表示不提供可用登录按钮，不表示平台本身不支持登录。国外平台与自定义内容管理系统已从当前平台枚举和接入范围移除。

## 部署边界

- 当前独立接口不做口令校验，也不加密数据库会话；只能放在受限内网或由反向代理统一限制访问，不要直接暴露公网。
- 数据库 `storage_state` 与备份包含可用 Cookie，应限制读取权限；日志与错误响应不得包含会话 JSON。多实例部署时扫码任务仍只保存在发起任务的实例内，需会话粘滞或先运行单实例。
- 知乎已完成真实登录联调；其他开放入口的平台目前只验证到登录页或二维码展示与未登录结论，仍需真实账号验证落库与恢复。短信或密码输入不保存原始凭据；需要在真实页面手动拖动的滑块等验证暂未接入。平台页面、账号接口或风控规则变化时应显示失败或未知；不要用 Cookie 是否存在代替登录验证。
- Playwright `storageState` 不保证覆盖所有网站的 `sessionStorage` 或浏览器绑定数据。因此其他平台必须分别验证登录态能否恢复，才能认定这条登录链路可用于后续预发布。

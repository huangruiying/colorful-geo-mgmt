# 策略模板迁移检查

## 评审范围

09-code-review：检查暂存、未暂存改动及配置到路由、模板、厂商策略、测试的关联引用。本次仅评审，保留用户目录调整，未修改业务源码。

## 发现

用户将 LLMStrategy、两个协议父类及 HTTP/引用工具移入 strategy.template，具体策略和路由留在 strategy。当前是包结构整理，没有新增路由或执行层，主源码引用已同步。

Java 17 clean package（跳过测试编译）通过。但独立编译 LlmSearchRequestTest 失败，确认 5 处错误：

| 测试行 | 原因 |
|---|---|
| 41 | 兼容 Chat 策略继承的 buildRequestBody 定义在 template 包，为 protected，原策略包测试不能直接访问 |
| 50 | 经 AbstractResponsesApiStrategy 类型调用 protected buildRequestBody，测试已不在同包 |
| 60 | 兼容 Responses 策略继承的 buildRequestBody 跨包不可直接访问 |
| 73、80 | parseResponse 是模板包内方法，不是外层具体策略可继承访问的方法 |

Spring 默认 Bean 名由具体类名生成，本次具体类名未变；路由和数据库 strategy_bean_name 不需修改。两个共用工具与模板仍在同包，当前包内访问可保留。

1. 保留现有目录结构及方法访问级别，不为测试把模板内部方法改成 public。

4. 调整后复跑路由、Spring Map 注入、渠道管理和协议测试。无需修改数据库、页面配置或新增注册表。

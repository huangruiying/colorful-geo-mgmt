# Workflow B —— 安全审查链（security-audit）

> 适用场景：安全巡检 / 高风险变更 / 涉敏感数据 —— 把"漏洞扫描 → 注入专项 → 依赖审计 → 评审收口"打成一条链。
>
> 触发关键词："漏洞 / 安全扫描 / SAST / 注入 / SQLi / XSS / SSRF / 反序列化 / 依赖 CVE / License / 升级"
>
> 核心原则：**08 入口分诊 → 三类专项并发 → 09 收口评审**，发现 CRITICAL 立即停链上报。

---

## 1. 串联顺序

```text
08 vuln-scan                  漏洞分诊
    ├─→ 10 injection-xss      注入专项
    ├─→ 11 dependency-audit   依赖审计
    └─→ 09 code-review        代码评审收口
```

---

## 2. 阶段定义

| 阶段 | Agent             | 目标                                  | 验收                          |
|----|-------------------|-------------------------------------|-----------------------------|
| 08 | vuln-scan          | 通用漏洞扫描，按严重度分级                       | CRITICAL/HIGH/MEDIUM/LOW 清单   |
| 10 | injection-xss      | SQLi / XSS / SSRF / RCE / 反序列化 专项检测 | 命中点 + PoC 思路 + 修复建议            |
| 11 | dependency-audit   | 三方依赖 CVE / License / 升级建议            | 阻塞依赖 / 可升级依赖 两份清单            |
| 09 | code-review        | 收口评审，确认上述发现已被处置                     | 无 CRITICAL/HIGH 遗留，LOW 有处置说明 |

10 / 11 / 09 之间**可并发**，08 出来后三个并发跑完一起汇总。

---

## 3. 输出契约

按 workflow.md 报告结果、证据和限制。**Risks 段必须含严重度**（CRITICAL / HIGH / MEDIUM / LOW），CRITICAL 必须独占一行并标 [BLOCK]。

---

## 4. 严守边界

- **不修代码**：本 workflow 只发现 + 建议，修复路由 04 / 05
- **不做架构 / 性能**：跨界路由 02 / 12
- **风险升级**：涉鉴权 / 密钥 / 数据隐私 → 加 26 威胁建模；大版本 / 灰度发布 → 加 28 链路演练

---

## 5. 触发示例

```text
"做一次安全巡检"                 → B
"这段代码有没有 SQL 注入风险"     → B（10 单跑亦可）
"我升级了几个依赖，扫一下"         → B（11 单跑亦可）
```

---

## 6. 与其他 Workflow 的关系

| 关系             | 说明                                            |
|----------------|-----------------------------------------------|
| 与 Workflow A 区别 | A 在涉敏感数据场景需"追加"调用 B；B 不能替代 A 的功能交付             |
| 与 26-threat-modeling | 26 是设计期建模；B 是实现期扫描，两者互补            |
| 与 09-code-review | 09 在 B 中是收口节点；其他 workflow 中 09 也可串联              |

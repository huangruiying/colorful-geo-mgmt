# 现有大模型策略独立实现检查

核对日期：2026-10-14。本轮只收敛已有实现，不新增通道或搜索流程。

## 最终结构

- 删除 `AbstractChatCompletionsApiStrategy` 和 `AbstractResponsesApiStrategy`。
- 通用 Chat、通用 Responses、OpenAI Chat、OpenAI Responses、豆包 Responses 五个策略直接实现 `LLMStrategy`，分别负责请求、HTTP 调用、正文、引用及元数据解析。
- 保留 `MockLlmStrategy`，实际 Spring 策略仍为六个，Bean 名、协议返回值及页面选项接口不变；现有数据库渠道及任务快照无需迁移。
- 各远程策略按名称注入同一个 `llmRestTemplateWithTimeout`，连接池及关闭责任仍归 Spring 配置。
- `LlmCitationParser` 移至策略包，只共用结构化引用解析，不负责请求、策略选择、搜索或网页抓取。`LLMStrategy` 接口位置和契约保留。
- 没有新增策略枚举、注册表、前端配置项、厂商占位策略、工具循环、应用侧搜索或资料拼接。

## 保持的请求与响应契约

| 策略 Bean | 当前范围 |
|---|---|
| chatCompletionsApiCommonStrategy | 基础 Chat 文本请求，不主动声明搜索 |
| responsesApiCommonStrategy | 基础 Responses 文本请求，不主动声明搜索或其他工具 |
| chatCompletionsApiOpenAiStrategy | 原 Chat 请求；仅精确匹配 gpt-5-search-api 时添加搜索选项并移除既有不发送的普通生成参数 |
| responsesApiOpenAiStrategy | Responses 的 web_search 与 required 工具选择 |
| responsesApiDoubaoStrategy | Responses 的 web_search、sources=[doubao] 与 required 工具选择 |
| mockLlmStrategy | 显式本地模拟，不调用远端、不作为失败降级 |

仍使用非流式完整响应；每次请求只携带本条独立问题。可选参数留空不传，填写后由接口校验。只接受回答中的结构化引用，保留按 URL 去重、豆包摘要兼容、缺失引用位置及原始 JSON 空值规则。失败或不完整 Responses 不算成功，单独的工具结果不当作回答正文。

## 架构复核

职责均保留在 infrastructure/client/llm：路由器选数据库渠道并查 Spring Bean Map，具体策略完成一次协议交互，统一结果对象只承载数据。独立策略中保留少量相同代码，避免厂商通过协议继承共同改变行为。现有 HTTP 资源仍共用；未新增资源所有者或事务边界。接口、DAO、页面和诊断任务的调用契约未改变。

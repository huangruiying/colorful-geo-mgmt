# 前端公共请求第一批验收

日期：2026-10-17。对应《前端架构分析与调整建议》第一批，只试点项目与模型页面。

## 变更范围与边界

- 新增 `static/admin/shared/http.js`，唯一出口 `AdminHttp.requestJson(path, options)`。沿用标准 fetch 参数，body 由原页面 JSON.stringify，响应保持原接口结构。
- projects.js、models.js 删除各自的请求封装，直接引用公共方法；4 个 HTML 在页面脚本前加载公共脚本，资源版本统一为 20261017-http1。
- 公共层合并 Headers，默认 Accept:application/json，有正文时补充 Content-Type；固定 no-store，透传 signal、method、body 等参数。
- 空成功响应返回 null；HTTP 错误优先显示 ProblemDetail.detail，无有效 detail 或非 JSON 错误仅显示 HTTP 状态；成功响应格式错误明确报错。不将完整响应挂到错误对象上。
- 请求或正文读取网络异常保留 cause；AbortError 原样抛出。只发送一次，不重试、不增加超时，不把前端取消当作服务端取消。
- 页面保存、跳转、表单字段、密钥留空保留、查询和启停流程不变；未接入其他业务页，未引入框架、npm 依赖、ES Modules、弹窗或 CSS 改造。
- 已有登录单测夹具 message 改为 detail，使其符合当前后端错误契约；未改登录生产代码。

## 方法与注释审计

| 方法/位置 | 实际阶段 | 职责说明与必要注释 | 决策/生命周期边界 | 结论 |
| --- | --- | --- | --- | --- |
| http.js#requestJson | 合并请求头 → 一次请求并读正文 → 统一响应解析 | 文件及方法说明入口、参数、空响应、异常；阶段注释说明无正文不设 Content-Type | AbortError 不包装；网络不确定不重发；不拥有页面或服务端任务生命周期 | 通过 |
| http.js#parseJsonResponse | 非空 JSON 解析 → HTTP 错误转换 → 返回原数据/null | 方法说明 ProblemDetail；解释错误报文不展示、204 不强制 JSON 解析 | 仅字符串且非空白的 detail 可作错误说明；解析失败保留 HTTP 状态 | 通过 |
| http.js#createResponseError | 构造带状态的 Error | 说明只保留状态、不附加请求与完整报文 | 无资源或重试行为；单阶段无需编号 | 通过 |
| 项目/模型页面请求调用 | 原请求点调用同一个公共入口 | 原有业务处理未改，删除局部 request，无转发包装 | 不改变提交字段、按钮恢复和导航条件；版本同步 | 通过 |
| Node 测试 createClient | 独立上下文装入真实公共脚本 | 说明网络替身；测试使用标准 Headers/Response | 每个用例隔离上下文，未 mock 核心解析方法 | 通过 |
| 浏览器脚本 | 接口拦截 → 四页实际操作 → 结果校验与拦截清理 | 文件头说明仅静态源码真实，业务接口全部替身 | 不触发真实创建/登录/模型/发布；验证错误恢复与空密钥契约 | 通过 |

架构复核：公共层只处理传输与响应边界，页面保留业务编排，真实复用已有两组页面调用；没有新增实体、接口转发层、全局业务状态或外部依赖。四页均通过正常 script 顺序显式声明依赖；其余页面保持原实现，留给后续批次。错误说明口径统一是本批已明确的调整。

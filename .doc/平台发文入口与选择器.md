## 2. 逐平台要点

### 百家号 BAIJIAHAO
- 早期用 `.../builder/author/static/home` 返回接口错误 `{"errno":10001402,"errmsg":"分数过低，请稍后再试"}`；正确的创作首页是 `https://baijiahao.baidu.com/builder/rc/home`。
- 编辑器为 React/Lexical 富文本，类名混淆（`FeEditorApp-*`），**优先用 `data-testid`**：`news-title-input`（标题容器）、`publish-btn`（发布）。标题是 contenteditable（placeholder 是同级 `div` 文本「请输入标题（2 - 64字）」）。
- 工具条按钮：`存草稿`、`预览`、`定时发布`、`发布`。正文 bodyText 含「正文／插入／智能标题／字数 0 已保存」等。
- **正文不在主文档**：主文档只有标题一个 `contenteditable`；正文是 UEditor 的 iframe（`<body class="view news-editor-pc" contenteditable="true">`）。必须按 frame 定位（见 §4.1）。

### B 站 BILIBILI
- 创作中心 `https://member.bilibili.com/platform/home`，「投稿」下含：视频投稿／短剧投稿／**专栏投稿**（href `/platform/upload/text`）／UP动画／互动视频投稿。
- 「专栏投稿」→ `.../upload/text/new-article`，其内嵌 iframe `york/read-draft` 是**草稿箱**（提示「可发专栏数 需 LV1+…LV1–3 每天 1 篇」），点其中「新的创作」进入 iframe `york/read-editor`（title「哔哩哔哩专栏编辑器」）即正文编辑器。
- **注意**：编辑器在 iframe 内，Java 端需 `frameLocator` 或按 frame URL 定位；直接打开 `.../upload/text/new-edit` 会得到空壳，必须走「新的创作」流程。

### 掘金 JUEJIN
- 编辑页 `https://juejin.cn/editor/drafts/new`（title「写文章 - 掘金」），左 Markdown、右预览。

- 顶部「草稿箱」「发布」；正文自动保存至草稿箱。首次访问有技术方向引导弹窗（点「跳过」）。
- **草稿保存机制（实测）**：页面**没有**「保存草稿」按钮；输入内容后编辑器会调 `POST api.juejin.cn/content_api/v1/article_draft/create`，但**编辑页 URL 不会跳转**（20–25s 仍为 `/editor/drafts/new`）。当前账号该接口返回 `403 must bind phone`，所以草稿箱一直是 0 条。成功判据应取该接口返回的 `draft_id`，不要依赖 URL（见 §4.3）。

## 3. 复现方法（探索工具链）

- 登录态来源：MySQL `platform_browser_login.storage_state`（Playwright JSON，Java/JS 通用）。探索时**只导出到本地临时文件**，不写入文档／日志。
- 工具：Node + Playwright（Chromium）驱动真实浏览器；脚本对每个平台执行「载入登录态 → 打开入口 → 截图 → 导出可交互元素（id/name/placeholder/aria/class/data-testid）」，对 iframe 内区域逐 frame 导出，对 SPA 用「点开后二次导出」定位编辑器。
- 真实提交（存草稿/发布）不在探索阶段执行；Java 客户端接入后再用受控测试内容验收。
- **复现客户端时序时必须对齐生产条件**：`PlaywrightBrowserComponent.openBrowser` 只传 `storageState`、**不设 viewport**，即 Playwright 默认 **1280×720**。视口尺寸会直接改变浮层/抽屉是否出现，用 1440×900 复现会漏掉头条的遮罩问题。

## 4. 首次真实联调失败根因诊断（2026-10-07 20:57–20:59，发布 #16/#17/#18）

背景：百家号／掘金／今日头条三个平台按上述选择器接入后做首次预发布联调，三条记录全部未成功，且三条耗时分别为 36s／35s／37s（≈ 一次 30s 超时 + 浏览器启动/导航），与 `colorful.geo.publish.browser.timeout-millis` 默认 30000 吻合。用真实登录态逐步复现后定位如下（**均已在真实会话中复现验证，非推断**）。

### 4.1 百家号 #18「编辑器无法打开，请检查浏览器登录态和网络」→ **误报，实为正文选择器错误**
- 截图证明编辑器**完全正常打开**（标题、正文占位、存草稿/预览/定时发布/发布 按钮齐全），登录态有效。
- DOM 探针：页面中 `[contenteditable="true"]` **只有 1 个**，且它就是**标题**（box 与 `news-title-input` 相同）。**正文是 UEditor 的 iframe**（`<body class="view news-editor-pc" contenteditable="true">`，父页面脚本为 `UE_V2.instants['ueditorInstant0']`）。
- 客户端 `BODY_SELECTOR = div[contenteditable="true"][data-lexical-editor="true"]` 取 `.nth(1)` → **count=0**，永远等不到 → `waitFor()` 空转 30s。
- 该超时发生在 `draftMayExist` 置位**之前**，于是被错归类为「编辑器无法打开」。**与登录态/网络无关。**
- 修法已验证：正文改用 frame 定位（`page.frames()` 中 body.className 含 `view` 的 frame），实测输入「GEO联调定位测试」→ 回读匹配 → 清空还原；标题选择器 `div[data-testid="news-title-input"] div[contenteditable="true"]` 正确。

### 4.2 今日头条 #17「草稿结果未确认」→ **自动弹出抽屉的全屏遮罩拦截点击**
- 编辑页会自动弹出「**头条创作助手**」抽屉，DOM 中存在覆盖整个视口的遮罩 `div.byte-drawer-mask`。
- 生产条件（默认视口 1280×720）复现：正文 box 中心 (640,570) 的顶层元素 = `div.byte-drawer-mask`，`click()` 一直重试到超时（实测 25s 超时；线上 30s → 总 35s）。
- `fill()` **不受遮罩影响**（Playwright 的 fill 不做点击命中检查，实测遮罩下 38ms 成功）→ 线上运行时**标题已填进去，卡死在正文 click**。因此这次运行**没有可用的草稿产出**。
- 修法已验证：导航后先清理浮层（点「我知道了」关闭引导/抽屉）→ 正文 click 22ms 通过、标题与正文回读全部匹配。
- 另有两点需在实现中处理：①侧栏存在「请完善账号信息，解锁发布文章、视频等权益功能」提示；②编辑页会自动载入历史草稿（本次为 `[无标题] 2022-10-26`），不能假设编辑器是空白。

### 4.3 掘金 #16「草稿结果未确认」→ **账号未绑手机号（403）+ 成功判据本身错误**
- 直接抓接口：输入标题与正文后，编辑器调用 `POST https://api.juejin.cn/content_api/v1/article_draft/create`，返回 **`{"err_no":403,"err_msg":"must bind phone","data":null}`** → 掘金账号**未绑定手机号，草稿创建被服务端拒绝**，故草稿箱恒为「文章草稿（0）」。
- 客户端第二个错误：用「URL 跳转到 `/editor/drafts/{id}`」判断草稿创建成功，但掘金编辑页 **URL 根本不跳转**（实测输入后 20s、25s 仍停在 `/editor/drafts/new`；页面也没有「保存草稿」按钮）。即使账号正常，这个判据也必然 30s 超时。
- 正确做法：读取 `article_draft/create` 的响应（`err_no=0` 且取 `data.draft_id`）；把 `403 must bind phone` 这类服务端明确拒绝归为**确定的失败**（可重试），而不是「结果待核对」。
- 账号侧动作：需先在掘金绑定手机号，否则代码改完也无法真正建草稿。

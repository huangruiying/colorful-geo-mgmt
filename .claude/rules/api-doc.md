# 接口文档生成规范

## 触发条件

当用户要求给前端、第三方或其他调用方提供接口说明时，进入本规范流程。

典型关键词：

- "接口文档" / "给前端接口文档" / "接口说明"
- "Request / Response" / "入参出参" / "字段说明"
- "新增接口" / "接口字段变更" / "错误码说明"

---

## 适用边界

本规范只负责单接口或多接口的调用说明，不负责完整技术详细设计。

- 只写接口调用方需要理解的内容
- 不展开实现逻辑、库表设计、灰度顺序、项目排期
- 如果用户要求"详细设计"、"技术方案"、"发版影响分析"，改用 `rules/tech-design-doc.md`

---

## 生成前必须确认的信息

缺少以下信息时先追问，不要猜测填充：

1. 接口名称与业务用途
2. 请求方法与接口地址
3. 调用方角色（前端、第三方、内部服务）
4. Request 字段清单：字段名、类型、是否必填、语义、默认值、枚举范围
5. Response 字段清单：字段名、类型、语义、枚举范围
6. 错误码 / 状态码
7. 鉴权方式与权限要求
8. 兼容性说明（新增字段、废弃字段、版本差异）

---

## 文档结构模板

输出 Markdown。多个接口按"接口一、接口二……"顺序分别成节，不合并。

````markdown
# 接口文档

## 接口一：{接口名称}

### 接口基础信息

- 提供服务：{服务名}
- 接口地址：{METHOD} {path}
- 调用方：{调用方}
- 鉴权方式：{鉴权方式，无则写"无"}

### Request

```json
{
  "field": "示例值"
}
```

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| field | string | 是 | 无 | 字段业务语义 |

### Response

```json
{
  "code": "000000",
  "message": "success",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | string | 业务响应码 |
| message | string | 响应信息 |
| data | object | 业务数据 |

### 错误码

| 错误码 | HTTP 状态码 | 说明 | 处理建议 |
|---|---|---|---|
| xxx | 400 | 参数非法 | 检查字段取值 |

### 兼容性说明

- 新增字段：
- 废弃字段：
- 版本差异：
````

---

## 写作规范

- Request / Response 必须使用 JSON 代码块，不允许写"json 串"占位
- 字段说明必须包含业务语义，不能只翻译字段名
- 枚举值、边界值、单位必须写清楚
- 新增字段只展示新增内容时，必须明确说明"仅展示新增字段"
- 接口地址禁止暴露表名、内部类名等实现细节

---

## 禁止行为

- 不得用 `data: any` 逃避字段定义
- 不得省略必填字段、错误码、鉴权要求
- 不得编造不存在的接口、字段、错误码
- 不得把完整技术详细设计内容塞进接口文档

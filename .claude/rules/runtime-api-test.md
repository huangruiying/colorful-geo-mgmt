# 运行时接口回归测试规范

本规范用于真实接口请求、日志归因、代码修复、重启回归、测试报告落地的闭环。单元测试规则见 `rules/testing.md`，不要在本文件重复单测设计细则。

## 0. 前置依赖检查（自动执行判断）

进入流程的**第一步**，两轮检查全部通过才开始执行，两轮任一有缺口均暂停等用户补充，补齐后写入项目 memory，再全自动继续。

### 第一轮：基础设施检查

读取项目 memory、用户输入和 IDE 真实启动配置，确认以下五项是否全部已知：

| 依赖项 | 说明 |
|---|---|
| 服务地址 | BASE_URL（本地端口或远端 IP） |
| 数据库连接 | host、port、user、password、database name |
| 日志路径 | logback-spring.xml 位置，或实际 info/error 日志文件路径 |
| 接口范围 | 来自用户提供的文档 / curl / 接口地址 / 当前分支 diff，任一即可 |
| IDE 启动配置 | IDEA / PyCharm / JetBrains 系列 IDE 中实际 Run/Debug 配置、工作目录、环境变量、VM 参数、程序参数、JDK / Python 解释器、Maven 配置 |

### IDE 真实配置强制规则

运行时接口回归涉及启动服务、重启服务、编译、运行脚本或连接外部资源时，必须优先读取 IDE 的真实配置，不允许凭系统默认值猜测。

读取优先级：

1. `.idea/runConfigurations/*.xml`
2. `.idea/workspace.xml` 中的 RunManager / recent_temporary 配置
3. `.idea/misc.xml`、模块 `.iml`、IDE 项目 SDK / language level 配置
4. 用户显式提供的启动命令、截图或 IDE 配置说明
5. 仍无法确定时，暂停并一次性询问缺口

必须从 IDE 配置中提取并用于执行：

- 启动类型：Spring Boot、Application、Maven、JUnit、Python、Shell 等
- 模块、主类、工作目录、classpath/module classpath
- VM 参数、程序参数、环境变量、Active profiles、`-D` 参数
- JDK 名称 / 路径 / language level；不得只按 `JAVA_HOME` 或当前 shell 的 `java` 推断
- Maven home、Maven settings、profiles、runner JRE、命令目标；不得只按系统 `mvn` 推断
- Python interpreter / SDK / venv、运行脚本、参数、环境变量；不得只按系统 `python` / `python3` 推断

目标启动类映射：

- 用户提供 Java / Python 启动文件绝对路径时，先根据源码根、包名、模块目录把文件路径解析为 FQCN / module path，再匹配 IDE Run/Debug 配置。
- 优先匹配已有配置名、main class、module 三者一致的 IDE 配置；匹配到配置后只读取其参数并组装等价启动命令，不操作 IDE GUI。
- 没有持久化 `.idea/runConfigurations/*.xml` 时，必须继续读取 `.idea/workspace.xml` 中的临时配置、最近配置和 RunManager；不能因为没有独立配置文件就改用系统默认命令。
- 匹配不到 IDE 配置时，不要求 IDE 创建临时配置；只能结合项目构建文件做静态分析并列出缺失的 IDE 配置或启动命令。
- 文件路径、包名、IDE 配置相互矛盾时，先记录冲突并暂停确认，不猜测启动类。

执行约束：

- IDE 配置存在时，以 IDE 配置为准；`pom.xml`、`.python-version`、`JAVA_HOME`、系统 PATH 只能作为校验或缺省补充，不能覆盖 IDE 真实配置。
- IDE 配置与构建文件冲突时，先记录冲突并按 IDE 配置执行；如果冲突会导致无法编译、无法启动或测试结论失真，暂停让用户确认。
- 没有 IDE 配置且用户未提供启动命令时，不自动猜测 Maven / JDK / Python 环境；只能完成静态分析，并明确列出缺口。
- 测试报告必须写明读取到的 IDE 配置来源、最终使用的 JDK / Maven / Python、启动命令或重启方式。

IDE 配置等价命令启动默认策略：

- 当 IDE Run/Debug 配置存在，且需要启动或重启目标服务时，默认只读取 IDE 配置，不操作 IDE GUI。
- 自动化执行方负责按 IDE 配置组装等价命令并启动服务；JDK / Maven / Python、工作目录、VM 参数、程序参数、环境变量必须来自 IDE 配置或由其校验确认。
- 自动化测试优先使用接口响应、日志文件、命令输出、数据库状态和源码定位问题；日志不会进入 IDE Run/Debug 控制台。
- 需要调试时，仍由自动化命令启动目标服务，并在启动参数中注入 JDWP；是否连接外部调试器由用户自行决定，不作为流程默认步骤。
- 重启前必须识别当前目标进程来源和启动参数，只允许停止与目标配置、主类、端口或命令行特征匹配的进程；无法确认时暂停并说明风险。
- 没有 IDE 配置且用户未提供启动命令时，不按系统默认 JDK / Maven / Python 猜测启动；只能完成静态分析，并明确列出缺口。

最低成本命令启动步骤：

1. 读取 IDE 配置并定位目标配置名、模块、主类 / 脚本、工作目录、参数、环境变量和运行时版本。
2. 将 IDE 配置转换为等价命令：Spring Boot / Application 使用 IDE 指定 JDK 和 classpath / module classpath；Maven 使用 IDE 指定 Maven home、settings、profiles、runner JRE 和 goals；Python 使用 IDE 指定 interpreter / venv、脚本和参数。
3. 启动前检查目标端口和目标进程；如已有匹配目标进程，先记录 PID 和命令行，再按需停止。
4. 用等价命令后台启动服务，保存 PID、完整命令、工作目录、环境变量摘要和日志采集位置。
5. 通过端口监听、健康检查或只读接口确认服务可用；失败时读取命令输出和日志文件归因。
6. 后续重启或 Debug 均基于同一 IDE 配置重新组装命令，不操作 IDE GUI，也不另起参数不一致的重复实例。

### 第二轮：接口 / 代码维度分析

基础设施检查通过后，分析接口范围（diff / 文档 / Controller），识别运行测试还缺哪些内容：

- **必填入参**：接口必填字段中，无法从数据库、代码默认值或上下文推断的值（如特定商户 code、外部回调 URL、加密密钥等）
- **必要配置**：新增的开关、阈值、Feature Flag，代码中有引用但 memory 或 Apollo 里找不到当前值的
- **外部前置条件**：测试链路依赖的第三方状态、账号、测试环境数据，AI 无法自行构造的

判断标准：**AI 能从现有代码、数据库、memory 中自闭环的不问；无法确定的才列出来问用户。**

两轮全部通过 → 全自动执行完整回归流程，无需逐步等待用户确认，直至测试报告落地。

有任何缺口 → 汇总所有缺失项一次性列出，**暂停流程**，等用户补充后写入项目 memory，再全自动继续。

## 1. 触发条件

用户要求以下任一事项时加载本规范：

- 跑接口测试 / 自动回归 / 真实请求接口
- 按 curl、接口地址、`.test` 文档或当前分支 diff 验证接口
- 生成 `.test` 测试脚本或测试报告
- 开发完成后确认是否执行真实接口回归

## 2. 强制边界

- 必须真实请求接口，不得只做脚本语法校验后声称通过。
- 所有输出使用中文，不自动提交 git commit。
- 修改代码前遵守项目规划确认要求；修改 Java 代码时遵守 `comment.md`、`comments/comment-java.md`、`refactor.md`。
- 每次代码修改后必须检查 `git diff` / `git status`。
- 只保留真实代码问题的修复；环境、外部依赖、测试绕路兼容不得长期留在业务代码中。
- 写接口依赖 `ContextUser`、登录态、权限、网关时，无登录态只记录为外部依赖问题，不长期改业务代码兼容匿名调用。
- 启动、重启、编译、脚本执行必须遵守 IDE 真实配置强制规则；缺少配置时不得用系统默认 JDK / Maven / Python 冒充真实运行环境。

## 3. 测试范围识别

先获取当前分支名，再按以下优先级识别测试范围：

优先级：

1. 用户提供的测试文档 / curl / BASE_URL / 接口说明
2. 用户指定接口地址
3. 当前分支 diff

如果只给接口地址，先定位 Controller、Service、Mapper、DTO，理解请求和响应结构。不生成接口文档，除非用户明确要求。

## 4. 测试数据准备

- 根据用户提供的数据库连接信息定位相关表。
- 查询真实可用样例数据，例如业务线、业务场景、主体 code、路由 code。
- 目标字段无数据时，允许插入最小测试数据验证链路。
- 测试数据必须写入报告；默认不清理测试数据，除非用户明确要求。

## 5. 自动化脚本

超过 2 个接口步骤时，优先在 `.test/` 下生成可执行脚本。

脚本环境变量：

- `BASE_URL`
- `AUTH_HEADER`
- `DB_USER`
- `DB_HOST`
- `DB_PORT`
- `DB_PASSWORD`
- `DB_NAME`
- `CURL_NO_PROXY`

脚本要求：

- `AUTH_HEADER` 可选；写接口因缺少登录态失败时归因为外部依赖问题。
- curl 默认加 `--noproxy '*'`，避免 localhost 或内网接口被代理劫持。
- 每一步必须断言，失败时打印请求结果、HTTP 状态码、接口响应。
- 可覆盖列表、详情、下拉/名称查询、管理列表、落库校验；写接口可测则执行，不可测则记录原因。

## 6. 真实请求与日志分析

- 优先请求用户给定 `BASE_URL`。
- localhost 请求失败时，区分沙箱网络、代理、端口、服务未启动。
- 必要时申请沙箱外执行 curl。
- 接口返回非预期时，必须查 `info.log` 和 `error.log`。
- 根据 `logback-spring.xml` 定位日志路径；默认路径找不到时，用 `lsof -p <java_pid>` 查实际打开的日志文件。
- 结合请求参数、trace、异常栈、代码行号定位原因；日志和代码结论不一致时，以日志栈 + 当前源码共同判断。

## 7. 问题归因

| 类型 | 判断标准 | 处置 |
|---|---|---|
| 代码问题 | 异常栈指向业务代码缺陷，或参数、分页、空集合、SQL、字段映射、枚举翻译等逻辑错误 | 可长期修改业务代码 |
| 环境问题 | 服务未启动、端口不可达、代理劫持、Apollo/Nacos/Redis/DB 不可用 | 只记录，不长期改业务代码 |
| 外部依赖问题 | `ContextUser`、登录态、网关鉴权、第三方服务不可用 | 可做临时 mock / stub / fake 验证链路，但不得长期改业务代码 |
| 数据问题 | 缺少测试数据、映射表数据、字典值导致结果异常 | 可插入最小测试数据并记录 |

### 7.1 外部依赖临时 mock

当测试依赖外部资源且当前环境无法满足时，允许自动生成临时 mock / stub / fake 代码继续验证内部链路，但必须把它视为非常规测试处理。

触发条件：

- 真实请求已执行，且日志、响应或连接结果能证明失败原因是外部依赖不可用、不可构造或无权限访问。
- 已优先尝试使用真实配置、测试数据、可用本地服务或配置开关解决，仍无法满足测试前置条件。
- mock 范围能被明确限定在本次测试链路，不改变接口长期语义，不绕过真实代码问题。

执行约束：

- 优先使用测试脚本 mock、临时本地 stub 服务、JVM `-D` 开关或测试专用 profile；必须改业务源码时，只能增加最小临时分支，并用显式开关控制默认关闭。
- 不得把外部依赖问题伪装成代码修复；不得把 mock 后通过等同于生产真实链路通过。
- 涉及登录态、`ContextUser`、权限、网关鉴权时，只能做测试态临时 mock，且必须说明未验证真实鉴权链路。
- mock 代码、临时开关、临时日志和测试绕路必须在测试结束前清理；若用户明确要求保留，必须只保留在 `.test/` 或测试专用代码中，并在报告中标明不属于生产修复。

报告要求：

- 说明无法满足的外部依赖、失败证据、采用的 mock 方式、影响接口、影响断言、涉及文件 / 参数 / 端口。
- 明确结论口径：真实外部链路未验证，当前只验证 mock 条件下的内部逻辑。
- 记录清理状态；清理后执行 `git diff` / `git status`，说明最终源码是否仍保留任何 mock 或非常规处理。

### 7.2 单次自愈回归

运行时接口回归允许在发现明确代码问题时自动修复一次，但必须防止循环。

触发条件：

- 第一轮真实请求失败，并且响应、日志、数据库状态、源码定位共同指向代码问题。
- 能定位到明确的最小修复点，例如空指针、字段映射、枚举翻译、分页参数、SQL 条件、响应封装等。
- 修复范围能按 04 / 05 的职责边界完成，不涉及需求变更、接口语义重写、大范围重构或外部依赖绕过。

执行顺序：

1. 读取首轮测试结果和已生成 / 暂存的测试报告，提取失败接口、请求参数、响应、日志证据、代码定位和归因类型。
2. 若归因为代码问题，路由到 04 / 05 做一次最小代码修改；如需改 Java，必须遵守 `comment.md`、`comments/comment-java.md`、`refactor.md`。
3. 修改后执行必要的编译 / 静态检查；失败则停止自愈，报告“修复后编译失败”，不继续重启。
4. 按 IDE 配置等价命令规则重启同一配置。
5. 只对失败接口和受影响的只读校验接口执行一次回归；必要时补充落库校验。
6. 更新同一份测试报告，记录“首轮失败 → 自动修复 → 重启 → 单次回归”的完整链路。

硬性限制：

- 自动修复最多 1 次，修复后重启最多 1 次，重启后回归最多 1 轮。
- 单次回归仍失败时，必须停止流程，不再继续修改代码；最终报告标记为“自动修复后仍失败”。
- 第二次失败只能做归因和建议，不得再次进入 04 / 05。
- 环境问题、外部依赖问题、数据问题不得触发长期代码修复；外部依赖问题只允许按 §7.1 做临时 mock，数据问题只允许插入最小测试数据并记录。
- 临时兼容、临时日志、测试绕路必须在流程结束前清理；清理后执行 `git diff` / `git status` 并写入报告。

## 8. 修复与回归

- 只修复已确认为代码问题的缺陷，保持范围最小。
- 修复后重新请求失败接口；自动修复只允许执行一次，详见 §7.2。
- 需要重启时，按以下顺序判断重启方式：
  1. 先读取 IDE 真实 Run/Debug 配置，并以其中的 JDK / Maven / Python、工作目录、VM 参数、程序参数、环境变量作为重启基线
  2. 默认由自动化命令按 IDE 配置等价启动或重启，不操作 IDE GUI，不要求 IDE 显示该服务
  3. 已有进程命令行含 `idea_rt.jar` 或其他 IDE 启动特征时，仍以 IDE 配置和当前进程命令行为参数来源；只停止与目标配置、主类、端口或命令行特征匹配的进程，不通过 IDE GUI 停止
  4. 接口响应、日志、数据库状态和源码仍不足以定位问题时，在等价启动命令中注入 JDWP 参数后重启；不自动操作 IDE Debug，用户需要时可自行连接外部调试器
  5. 命令行等价启动规则：`ps -p PID -o args=` 取完整命令行 → 正则删除 IDE javaagent 参数 → 保留 IDE 配置中的参数 → 注入本次测试需要的 `-D` 参数；需要 Debug 时再注入 JDWP 参数 → 原工作目录后台重启 → 健康检查轮询；不要尝试重新构建 jar
  6. IDE 配置明确是 Maven / Spring Boot 启动：按 IDE 配置中的 Maven home、settings、profiles、runner JRE、goals 执行；不要退回系统默认 `mvn`
  7. IDE 配置明确是 fat-jar 启动：按 IDE 配置中的 JDK、工作目录、VM 参数和环境变量自动重启
  8. IDE 配置明确是 Python 服务：按 IDE 配置中的 interpreter / venv、脚本、参数、环境变量重启；不要退回系统默认 `python`
  9. 均无法识别时，说明无法自动重启并等待用户手动重启
- 切换 Apollo 配置进行测试时，优先用 JVM `-D` 参数注入（优先级高于 Apollo 远程配置），不要修改 Apollo 本地缓存文件（远程 Config Server 启动时会覆盖本地文件）；`@Value` 不支持热更新（无 `@RefreshScope` 时），修改配置后必须重启服务，不能只调 `actuator/refresh`
- 重启后先请求健康检查或只读接口，再执行回归。
- 临时外部依赖兼容必须在测试结束后清理；清理后再次执行 `git diff` / `git status`。

### 8.1 启动成功判定

按 IDE 配置等价命令启动后，按以下顺序确认服务状态：

1. 启动命令已记录 PID、工作目录、完整命令和日志采集位置。
2. `ps -p <pid> -o pid,ppid,command` 显示目标进程仍存活，命令行中的主类 / 脚本 / Maven goal / Python interpreter 与 IDE 配置一致。
3. `lsof -nP -iTCP:<port>` 显示目标 Java / Python 进程监听端口。
4. `curl --noproxy '*' -i <BASE_URL>/<path>` 返回任意 HTTP 响应即代表服务可达；404 只代表 endpoint 不存在，不等于服务未启动。
5. 沙箱内 curl 连接失败但 `lsof` 显示端口监听时，优先按沙箱网络差异处理，申请沙箱外 curl 复核，不要直接判定服务失败。
6. 如果没有可用健康检查接口，优先请求一个只读业务接口；仍无接口时，仅记录“进程和端口已就绪，接口活性未验证”。

## 9. 测试报告

测试完成后在 `.test/` 生成：

```text
<分支>/<分支>_<年月日时分秒>-测试报告.md
```

时间必须取当前实际时间。报告必须包含：

- 分支、测试时间、测试服务地址
- 测试范围、测试数据
- 每个接口的请求结果、关键返回字段
- 日志证据、代码定位、问题归因
- 修复内容、回归结果、未覆盖项
- 是否清理测试数据
- 当前源码保留了哪些改动
- 运行实例状态与当前源码状态，避免临时兼容和最终源码混淆
- IDE 配置来源、最终使用的 JDK / Maven / Python、启动命令或重启方式
- 启动模式：读取 IDE 配置后的命令行等价启动；如注入 JDWP，说明调试端口；说明日志采集来源
- 单次自愈回归记录：是否触发、修复文件、重启方式、复测接口、复测结果；如未触发，说明未触发原因
- 非常规处理记录：所有 mock / stub / fake、临时配置、临时日志、沙箱外请求、临时数据、临时代码绕路的原因、范围、证据、影响、清理状态
- 固定说明：`写接口依赖 ContextUser / 登录态 / 权限时，无真实鉴权条件默认归因为外部依赖问题；如使用临时 mock，必须说明未验证真实鉴权链路，不长期改业务代码`

## 10. 最终输出

- 简要说明测试是否通过。
- 明确通过、失败、未测接口。
- 明确失败原因属于代码、环境、外部依赖还是数据。
- 给出测试报告路径。
- 如保留测试数据，列出关键主键或 code。

## 11. 已知技术陷阱（快查表）

> 执行自动化脚本时的高频死坑，命中后直接按"正确做法"处理，不要重复探索。详细代码示例见各项目坑文档。

| 陷阱 | 判断特征 | 正确做法 |
|---|---|---|
| 旧版 Redis（< 6.0）不支持 HELLO 命令 | 报 `-ERR unknown command 'HELLO'` | 用原生 socket + RESP 协议连接；`$N` 是实际字节数，含特殊字符的密码要逐字节计数 |
| macOS 获取 Java 进程完整命令行 | `ctypes KERN_PROCARGS2` 返回空或权限错误 | `ps -p PID -o args=`，ps 本身有内核级权限，不截断 |
| 含空格的 javaagent 路径被误分割 | 命令行含 `IntelliJ IDEA.app`，`.split()` 后参数截断 | 正则 `[^=]*` 匹配含空格路径后整体删除，再 `split()` |
| Apollo 本地缓存文件修改不生效 | 启动日志出现 `Located meta services from apollo.meta` | 用 JVM `-D` 参数覆盖（优先级高于 Apollo），不要改本地缓存文件 |
| `@Value` 修改配置后不生效 | 调 `actuator/refresh` 后字段值未变 | `@Value` 是一次性注入，必须重启服务；只有加了 `@RefreshScope` 的 Bean 才支持热更新 |
| IDEA 参数等价重启 | 命令行含 `idea_rt.jar` 或 IDE 配置中没有 fat-jar | `ps` 取命令行 → 正则删除 IDE javaagent 参数 → 合并 IDE 配置参数 → 注入 `-D` 新值 → 原工作目录后台重启 → 健康检查轮询 |
| JDK / Maven / Python 版本跑偏 | shell 中 `java`、`mvn`、`python` 与 IDE 配置不一致 | 以 IDE Run/Debug 配置、项目 SDK、runner JRE、interpreter / venv 为准，系统 PATH 只做兜底校验 |

- 创作平台 `https://creator.xiaohongshu.com/` →「发布笔记」→ tab：上传视频／上传图文／`写长文`／发播客。

- **入口流程（2026-10-09 真实 UI 校正，修复"小红书发布失败"）**：新版创作中心首页落在 `/new/home`，「发布笔记」已**不是** `<button>`（首页 `button` 数为 0，`button:has-text('发布笔记')` 命中 0 → 30s 超时）；发布页默认视频 tab（`target=video`），必须先切「写长文」tab 才出现「新的创作」，且该 tab 元素被同位置兄弟节点遮挡，普通 `click()` 会超时（旧代码 `.creator-tab:has-text("写长文").click()` 因此失效）。
  - **现固定入口**：直接深链 `https://creator.xiaohongshu.com/publish/publish?from=menu&target=article` → 点 `button.new-btn`（「新的创作」）→ 长文编辑器出现在同页。去掉了"首页发布笔记 + 切写长文 tab"两步，避免遮挡与超时。
- 客户端实现：进「写长文」发布页 → 点「新的创作」→ 填标题（textarea fill）→ 正文（ProseMirror 聚焦后 `keyboard().insertText`）→ **离开编辑器前页内回读标题与正文**确认 → 点「暂存离开」存草稿。编辑器 URL 恒为 `?from=menu&target=article`（**不含草稿 id**），故 `remoteContentId` 返回 null，且 **"打开草稿"无法给单篇深链**——`createDraft` 返回的 `draftUrl` 指向创作者中心首页 `https://creator.xiaohongshu.com/new/home`（其「草稿箱」卡片可进入草稿），由用户在其中点开具体草稿。注意：`new/note-manager`（笔记管理）只含"已发布/审核中/未通过"、**没有草稿 tab**，草稿不在笔记管理里。
- **★根因（2026-10-10 最终定论，推翻此前"反爬风控拦住保存接口"的归因）：小红书网页版草稿存在「浏览器本地存储（IndexedDB）」，不在服务端。** 铁证：
  - 发布页草稿箱（`publish/publish?from=menu&target=article` 内 `草稿箱` tab，`new/note-manager` 无草稿）原文：**「草稿存储于当前使用的浏览器本地，在清除浏览器数据时会被删除；视频笔记最多支持保存100篇草稿…」**；
  - **同一浏览器实例**内「写长文 + 暂存离开」后，草稿箱计数 `0→1`、`长文笔记(1)`（`XiaohongshuLocalDraftVerify`）；**换一个全新浏览器实例**再看仍是 `草稿箱(0)`（`XiaohongshuDraftBoxFind`）→ 本地存储不跨实例共享；
  - 草稿内容在 **IndexedDB**（不在 localStorage）。
- **所以「打开草稿找不到」= 架构不匹配，与链接错／headless／风控都无关**：系统用**一次性临时浏览器**建草稿，草稿只写进该临时 profile 的本地存储，浏览器一关（Playwright 临时 profile 销毁）即消失，用户在**自己的浏览器/App 里永远看不到**。
- **XHS ≠ 头条**：头条草稿是**真发服务端请求**（所以"有界面能存、无界面被风控拦"）；小红书草稿**纯本地、根本不发网络请求**。此前观察到的"点击暂存离开后零 save/note/publish 请求"现象正确，但归因（反爬 gate 保存接口）**是错的**——因此 CDP 真实 Chrome 指纹、逆向签名保存接口**都不能解决**（压根没有"保存接口"可调）。

- **待确认**：长文页未出现明确的「发布」按钮，需在实际联调时进一步确认发布触发方式（疑与「长文合集」／自动保存相关）。

## 3. 复现方法（探索工具链）

- 登录态来源：MySQL `platform_browser_login.storage_state`（Playwright JSON，Java/JS 通用）。探索时**只导出到本地临时文件**，不写入文档／日志。

### 4.1 百家号 #18「编辑器无法打开，请检查浏览器登录态和网络」→ **误报，实为正文选择器错误**

### 4.2 今日头条 #17「草稿结果未确认」→ **自动弹出抽屉的全屏遮罩拦截点击**

## 5. 生产环境须知（2026-10-09）：运行期浏览器不可继承 AI 工具本地代理 + Playwright 缓存坏锁

> 以下两条是 2026-10-09 接入 TOUTIAO/BAIJIAHAO 时暴露的**运行环境**问题，与具体平台选择器无关，影响**全部**浏览器发文平台。

### 5.1 代理污染：`HTTP(S)_PROXY` 会被 Chromium 继承（已修）

- 运行环境存在 `HTTP_PROXY`/`HTTPS_PROXY`＝`http://127.0.0.1:57162`（本机 AI 工具的**本地透明代理**，非通用 HTTP 代理）。`PlaywrightBrowserComponent.openBrowser` 启动 Chromium 时会继承这些变量，把常规网页请求（mp.toutiao.com、baijiahao.baidu.com 等）路由到该非通用代理，导致页面加载异常或 `chromium().launch()` 直接挂死。
- **复现**：独立 runner 直接调真实 `ToutiaoBrowserClient`/`BaijiahaoBrowserClient`，保留代理变量时 `Playwright.create()` 卡死（无输出、>150s）；`env -u` 清掉代理变量后 14s/12s 即 `DRAFT_CREATED`。
- **修复**：`PlaywrightBrowserComponent.openBrowser` 启动 Chromium 时显式加 `--no-proxy-server`（`new BrowserType.LaunchOptions().setArgs(List.of("--no-proxy-server"))`），强制发布浏览器走直连，不继承运行环境代理。改后单测 `PlaywrightBrowserComponentTest` 同步更新 mock（匹配 `launch(LaunchOptions)` 重载）。
- **注意**：若机器本身确需代理才能出网（本环境不需要），应改为按真实代理显式配置，而非继承 AI 工具代理。

### 5.2 Playwright 浏览器缓存坏锁 `__dirlock`（环境损坏，需人工清理）

- 路径：`~/Library/Caches/ms-playwright/__dirlock`（空目录）。`Playwright.create()` 每次都会走 `DriverJar.installBrowsers`，该步骤会触碰/清理 `__dirlock`；若该锁处于残留态且 macOS 安全策略拒绝删除，会抛 `Failed to install browsers / [safe-delete] broker denied delete: .../__dirlock` → `RuntimeException: Failed to create driver`，**所有浏览器发文全部失败**。
- **成因**：诊断过程中多次强制杀掉 Java 进程（`System.exit`/SIGTERM）会留下未关闭的 Chromium 子进程，并可能中断安装步骤、留下坏锁。
- **绕行（不改生产代码）**：给应用进程设置 `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`，`Playwright.create()` 跳过安装步骤、不再触碰 `__dirlock`，浏览器即可正常启动（已验证：默认缓存目录 + 该变量 + 保留代理 + 代码层 `--no-proxy-server` → 头条/百家号均 `DRAFT_CREATED`）。
- **彻底修复（需用户执行，AI 工具无权限删除该受保护目录）**：删除坏锁即可恢复——`rm -rf ~/Library/Caches/ms-playwright/__dirlock`，随后重启应用。删除后 `Playwright.create()` 会正常重建该锁。
- **教训**：诊断强杀会污染 Playwright 缓存锁；以后独立 runner 跑真实浏览器验证时，统一用 `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` + 一份干净的 `PLAYWRIGHT_BROWSERS_PATH`（已复制一份到 `/tmp/pw-browsers` 供本机临时验证）启动，避免踩锁。

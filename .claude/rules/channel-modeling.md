# 外部系统交互报文建模规范

> 本规范用于判断系统与外部依赖交互时，何时建立独立 Request / Response / Callback 对象，何时允许使用 `Map` / `JSONObject`。目标是在外部契约边界清晰的前提下，避免无实际收益的 DTO 膨胀。

## 0. 适用范围

本规范适用于系统与第三方通道、供应商平台、开放平台及其他外部依赖之间的交互报文，包括：

- 出站请求：当前系统主动调用下游接口的请求报文。
- 下游响应：外部依赖同步或异步返回的响应报文。
- 入站回调：外部系统主动调用当前系统的通知、回调报文。
- 公共协议：外部网关公共头、签名信封、分页、回调公共结构等协议报文。

本规范不适用于：

- 项目内部 Service / Domain 方法参数。
- 内部领域模型、聚合和值对象。
- 数据库实体、持久化对象。
- 不经过外部系统边界的普通内部 DTO。

## 1. 核心原则

```text
外部通用协议结构必须建模；
简单、扁平、单点、即时消费的业务报文可以使用 Map / JSONObject；
出现复用或业务复杂度时必须升级为对象。
```

请求、响应和回调必须分别判断，不要求采用相同形式。请求简单时可以使用 `Map`，响应或回调复杂时仍应建立独立对象，反之亦然。

## 2. 判断顺序

按以下顺序判断，命中前一项后不再向下放宽：

1. 是否属于外部系统公共协议结构？是，则必须建立对象。
2. 是否存在复用、复杂结构或业务约束？是，则必须建立对象。
3. 是否同时满足简单、扁平、单点使用、即时消费？是，才允许使用 `Map` / `JSONObject`。

## 3. 必须建立对象的场景

满足任意一项，必须建立独立 Request / Response / Callback 对象：

- 属于外部系统公共协议层，例如统一网关公共头、签名信封、分页结构、回调公共结构。
- 被两个及以上调用点复用，或需要跨 Service / Handler / Client 层传递。
- 包含嵌套对象、集合、条件字段、多种响应形态或多态结构。
- 需要字段校验、默认值、格式转换、脱敏或自定义序列化。
- 字段之间存在业务约束，例如“传 A 时必须传 B”。
- 需要兼容多个接口版本、历史字段或通道差异。
- 响应需要状态转换、跨层传递、落库或参与后续业务流程。
- 业务字段较多；超过 5 个字段时默认优先建模，除非能够明确证明 Map 更清晰。

通用协议对象必须放在对应外部系统或通道的基础文件目录中，不得散落在业务 Service / Handler 内。

## 4. 允许使用 Map / JSONObject 的场景

只有同时满足以下条件，业务报文才允许直接使用 `Map` / `JSONObject`：

- 仅有一个调用点。
- 报文结构扁平，没有嵌套对象或集合。
- 业务字段不超过 5 个左右。
- 不包含条件字段、复杂校验、版本兼容或自定义序列化。
- 请求组装后立即序列化，不跨层传递。
- 响应读取后立即校验并转换为项目业务模型，不继续透传原始 JSON。
- 金额、状态等关键字段能够使用明确类型读取和严格校验。

典型场景：只包含少量固定查询条件的单点下游查询 `body`，可以直接使用 `Map<String, Object>`；对应的简单响应可以直接使用 `JSONObject` 读取。

## 5. Map / JSONObject 使用边界

- 禁止让原始 `Map` / `JSONObject` 跨业务层传递。
- 禁止使用无类型强制转换读取金额；金额必须使用 `BigDecimal`。
- 必填字段缺失必须明确失败，禁止默认成 `0`、空字符串或成功状态。
- 同一协议字段在两个以上位置重复组装或读取时，应提取常量或升级为对象。
- Map 处理中出现多个条件分支、兼容逻辑或字段转换时，必须升级为对象。
- 请求、响应和回调字段名必须与外部接口文档保持一致，不得为迁就项目命名随意改写。
- 允许 Map 不代表允许省略业务校验；系统响应、业务响应、金额和状态仍需分别校验。

## 6. 分层职责

- Client / Gateway：负责外部通用协议组装、签名或加解密、HTTP 调用、公共响应解析。
- 业务 Service：负责简单业务 `body` 的 Map 组装、业务字段校验和项目模型转换。
- Common：只维护多个业务共同使用的响应码、字段标准化和公共判断。
- 状态枚举：只负责通道状态到内部状态的映射，不解析 JSON、不执行外部调用。
- Callback Handler：负责接收和校验入站回调，复杂或复用的回调契约必须建立对象。

## 7. 升级触发条件

原本使用 Map / JSONObject 的报文出现以下任一变化时，必须在本次改动中升级为独立对象：

- 新增第二个调用点。
- 新增嵌套结构、集合或条件字段。
- 新增字段间联合校验。
- 新增版本兼容、字段别名或默认值策略。
- 原始报文需要跨层传递或持久化。
- 单个组装或解析方法已经无法保持线性、清晰。

## 8. 评审检查

- 外部公共协议结构是否错误地使用了 Map。
- 单点简单业务报文是否建立了无收益 DTO。
- Request 与 Response 是否分别评估，而不是机械成对创建。
- 入站 Callback 是否按独立方向评估，而不是机械复用出站 Response。
- Map / JSONObject 是否跨层泄漏。
- 金额、状态和必填字段是否明确类型化并严格校验。
- 业务复杂度增加后是否及时从 Map 升级为对象。

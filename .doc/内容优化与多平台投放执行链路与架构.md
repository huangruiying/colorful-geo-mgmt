# 内容优化与多平台投放执行链路与架构

## 当前边界

本期完成内容优化结果入库、预发布弹窗确认最终稿、逐平台创建草稿及结果查询。`prePublish` 只创建草稿，不等于公开发布；针对已有草稿的 `publish` 按钮及其状态迁移留待下一阶段。账号凭据不写入业务表。

## 执行链路

```text
输入标题、原文和可选优化偏好
  → ContentOptimizationService 调用当前启用的大模型
  → 保存原文、优化稿、策略、提示与引用
  → 勾选一篇内容，在预发布弹窗中检查或修改最终稿并选择平台
  → 用户确认后，逐平台写入标题和正文快照（INITIALIZED：0）
  → 逐平台推进状态（PRE_PUBLISHING：1）
  → ContentPublicationService.prePublishContent 串行执行平台策略
  → 回写 PRE_PUBLISHED：2 / PRE_PUBLISH_FAILED：5、草稿链接及平台实际返回的 ID
  → 页面查看逐平台发布记录；未知结果先人工核对，不自动重试
```

## 分层落点

| 层 | 当前职责 |
|---|---|
| `presentation/controller/ContentOptimizationRecordController` | 优化入库、分页列表、详情、确认稿批量预发布接口 |
| `application/content/ContentOptimizationRecordApplicationService` | 编排优化、逐平台记录创建与结果回写 |
| `domain/service/optimization/ContentOptimizationService` | GEO 优化规则、提示词与大模型结果转换 |
| `domain/service/publish/ContentPublicationService` | 复用已有逐平台草稿创建能力 |
| `domain/service/content` | 基于 MyBatis-Plus `ServiceImpl` 保存优化记录和发布记录 |
| `infrastructure/repository` | `BaseMapper` DAO、表实体及少量分页聚合与条件更新 SQL |
| `infrastructure/client/publish/strategy` | 平台协议与执行差异，不处理数据库 |
| `static/admin/contents.html` | 同端口管理页面、最终稿确认及多平台选择弹窗 |

## 数据与状态

空库建表脚本是 [`src/main/resources/db/mysql/001_init.sql`](../src/main/resources/db/mysql/001_init.sql)，旧库迁移脚本是 [`src/main/resources/db/mysql/002_content_publish_record.sql`](../src/main/resources/db/mysql/002_content_publish_record.sql)，本地 Docker 操作见 [`docker/README.md`](../docker/README.md)。数据库为 MySQL 8.4，表均使用 InnoDB、`utf8mb4`。

- `content_optimization_record`：保存标题、原文、优化稿、优化偏好、实际策略、警告、结构化引用和时间。优化失败不会写入半成品记录。旧库迁移保留历史 `final_content`、`content_status` 列以避免丢失旧稿，新代码不再读写。
- `content_publish_record`：用户点击预发布并确认后才创建；每个平台保存关联优化记录 ID、平台、确认稿标题和正文快照、状态、平台返回的 `remote_content_id`、草稿链接、公开链接、失败原因和时间。`(content_record_id, platform_type)` 唯一，重复点击不再生成草稿。
- 状态主链路为 `INITIALIZED(0) → PRE_PUBLISHING(1) → PRE_PUBLISHED(2) → PUBLISHING(3) → PUBLISHED(4)`。明确失败分别是 `PRE_PUBLISH_FAILED(5)`、`PUBLISH_FAILED(6)`。如果预发布结果不确定，记录保留 `PRE_PUBLISHING` 并写说明，供人工核对，不自动重试。
- 只有平台明确返回远程 ID 时才保存 ID；只返回草稿链接的平台不会伪造 ID。未实现工作台公开发布，因此本期不会由工作台写 `PUBLISHED`。

## 页面和接口

管理页：`/admin/contents.html`，从 `/admin/index.html` 的侧栏进入。在详情中查看原文、优化稿、警告和引用；勾选一篇内容或点行内“预发布”，在弹窗中检查或修改最终稿并选择平台，确认后才创建发布记录。已有发布记录的平台不可再选。

| 方法与路径 | 用途 |
|---|---|
| `POST /content-records/optimize` | 优化并保存内容 |
| `GET /content-records?page=0&size=20` | 内容摘要分页 |
| `GET /content-records/{id}` | 原文、优化稿和逐平台发布记录详情 |
| `GET /publication/platforms` | 快速获取已配置发布策略的平台列表，不等待登录探测 |
| `POST /content-records/{id}/pre-publish` | 接收 `publicationTitle`、`publicationContent`、`platformTypes`，确认稿后逐平台创建草稿并保存结果 |

## 后续阶段

为已创建草稿的逐平台发布记录增加真正的 `publish` 操作、公开链接回写和页面按钮。部分平台没有草稿 ID 或没有公开发布能力，需要按具体平台策略先补齐，不能仅凭草稿链接推断公开发布成功。是否支持失败记录重试、同平台重复发布、审核角色和平台适配稿，须分别定义规则后再扩展当前唯一键和状态机。

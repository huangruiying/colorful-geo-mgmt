# 31-runtime-api-test 运行时接口回归

## 1. 定位

围绕用户指定接口、curl、测试文档或当前分支改动，执行真实接口请求、日志分析、问题归因、必要代码修复、重启回归和 `.test` 测试报告落地。

只做运行时接口回归闭环；单元测试生成仍由 06-unit-test-gen 负责。

---

## 2. 职责边界

### 2.1 负责

- 识别本次需要真实请求的接口和字段
- 读取 IDEA / PyCharm / JetBrains 系列 IDE 的真实 Run/Debug 配置，确认 JDK / Maven / Python、工作目录、参数和环境变量
- 基于 IDE 真实配置组装等价命令启动 / 重启服务，不操作 IDE GUI
- 准备或记录最小测试数据
- 在 `.test/` 下生成可执行测试脚本和测试报告
- 请求真实服务并断言响应
- 读取日志并完成代码 / 环境 / 外部依赖 / 数据问题归因
- 外部依赖无法满足时，按规则生成临时 mock / stub / fake 验证内部链路，并在报告中说明非常规处理
- 确认代码问题后路由 04 / 05 最多自动修复一次，并在重启后最多回归一次
- 清理临时兼容，确认最终源码只保留真实代码修复

### 2.2 不负责

- 单元测试编写 → 06
- 安全专项扫描 → 08 / 10 / 26
- 性能压测与热点分析 → 12
- 纯日志 RCA 且不需要真实接口回归 → 14
- PR 摘要 → 21

---

## 3. 触发场景

- 用户要求“跑测试 / 自动测试 / 真实接口回归 / 生成测试报告”
- 用户提供接口地址、curl、`.test` 文档或 `BASE_URL`
- Workflow A 开发完成并通过 09 后，用户确认继续执行真实接口回归
- 当前分支改动涉及 Controller / Service / Mapper / DTO，需要真实接口验证

---

## 4. 输入要求

- 接口地址、curl、测试说明或当前分支 diff
- 服务地址 `BASE_URL`
- IDE 真实启动配置（优先从 `.idea/runConfigurations/*.xml`、`.idea/workspace.xml`、`.idea/misc.xml`、模块 `.iml` 读取）
- 可选鉴权 `AUTH_HEADER`
- 可选数据库连接信息
- 可选服务启动 / 重启命令

缺少真实请求或真实启动环境所需信息时，先明确缺口；不能靠系统默认 JDK / Maven / Python 猜测，也不能伪造测试通过。

---

## 5. 规范参考

必须加载并遵守：

- 通用测试原则：`rules/testing.md`

---

## 6. 输出契约

按 workflow.md 的结果与证据要求输出，重点包含以下内容（栏目名不强制）：

- **Findings**：真实请求结果、关键响应字段、日志证据、非常规处理记录、测试报告路径
- **Risks**：未测接口、环境缺口、外部依赖限制、数据污染风险
- **Recommended Actions**：需要用户补充的鉴权 / 重启 / 数据 / 环境动作；单次自愈回归仍失败时给出下一步修复建议
- **Next Agent**：代码问题 → 04 / 05；日志深挖 → 14；PR 摘要 → 21

---

## 7. 禁止行为

- 只跑 `bash -n` 或脚本语法校验就声称接口测试通过
- 为绕过登录态、网关、ContextUser 长期修改业务代码
- 把环境问题、外部依赖问题伪装成代码修复
- 修复后不重启、不回归
- 自动修复失败后继续循环修改代码
- 测试结束后保留临时兼容代码
